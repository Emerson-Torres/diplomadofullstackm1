HttpClient

El modulo oficial de Angular para consumir APIs. Mismo concepto que fetch() o $.ajax(), pero integrado con el sistema de Angular.

Observable vs Promise

La diferencia principal con fetch() es que HttpClient devuelve un Observable en lugar de una Promise. Funcionalmente para este proyecto son equivalentes, pero el Observable tiene mas capacidades:

fetch() — Clases 1 a 5
async function cargar() {
  const res  = await fetch('url');
  const data = await res.json();
  this.data = data;
}
HttpClient — desde Clase 6
ngOnInit(): void {
  this.http.get('url').subscribe(
    (response) => {
      this.data = response;
    }
  );
}
Por que .subscribe()? Un Observable es como una "suscripcion a una revista": no llegan los datos hasta que te suscribes. .subscribe(callback) es el equivalente a .then(callback) en Promesas. El callback recibe los datos cuando llegan.

Paso 1 Activar HttpClientModule en app-module.ts

HttpClient no esta disponible por defecto. Hay que importar HttpClientModule en app-module.ts. Se hace una sola vez y queda disponible en toda la aplicacion:

src/app/app-module.ts — agregar HttpClientModuleTypeScript
import { NgModule } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { AppRoutingModule } from './app-routing-module';
import { AppComponent } from './app';
import { HttpClientModule } from '@angular/common/http';  // AGREGAR
import { ProductsComponent } from './products/products';
import { ProductCardComponent } from './product-card/product-card';

@NgModule({
  declarations: [
    AppComponent,
    ProductsComponent,
    ProductCardComponent
  ],
  imports: [
    BrowserModule,
    AppRoutingModule,
    HttpClientModule   // AGREGAR AQUI
  ],
  providers: [],
  bootstrap: [AppComponent]
})
export class AppModule { }
Un error comun es intentar usar HttpClient sin agregar HttpClientModule a imports. El error que aparece es NullInjectorError: No provider for HttpClient. La solucion es siempre revisar que HttpClientModule este en el array imports de app-module.ts.

Servicios

Una clase con Injectable() que centraliza la logica de negocio. Los componentes consumen el servicio sin conocer los detalles de la API.

Por que usar un servicio?

Codigo que se vuelve dificil de mantener
// En ProductsComponent.ts
constructor(private http: HttpClient) {}

ngOnInit() {
  this.http.get('...fakestoreapi.com/products')
    .subscribe(r => this.data = r);
}

// En ProductDetailComponent.ts — repetido
constructor(private http: HttpClient) {}

ngOnInit() {
  this.http.get('...fakestoreapi.com/products/'+id)
    .subscribe(r => this.detalle = r);
}
Como mejorar: centralizar en un servicio
// En product.service.ts — un solo lugar
getProducts() {
  return this.http.get('...fakestoreapi.com/products');
}
getProductById(id) {
  return this.http.get('...fakestoreapi.com/products/'+id);
}

// En cualquier componente — simple y limpio
ngOnInit() {
  this.productService.getProducts()
    .subscribe(r => this.data = r);
}

Paso 3 Escribir product.service.ts

src/app/services/product.service.tsTypeScript
import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable({
  providedIn: 'root'  // disponible en toda la app sin registrar en app-module.ts
})
export class ProductService {

  private apiUrl = 'https://fakestoreapi.com/products';

  constructor(private http: HttpClient) { }

  getProducts(): Observable<any[]> {
    return this.http.get<any[]>(this.apiUrl);
  }

  getProductById(id: number): Observable<any> {
    return this.http.get<any>(`${this.apiUrl}/${id}`);
  }

  getProductsByCategory(category: string): Observable<any[]> {
    return this.http.get<any[]>(`${this.apiUrl}/category/${category}`);
  }
}

Paso 4 products.ts actualizado

Los cambios son minimos: se agrega la inyeccion del servicio en el constructor y se actualizan los metodos que hacian referencia al mock. El template HTML no requiere ninguna modificacion.

src/app/products/products.ts — version Clase 6TypeScript
import { Component, OnInit } from '@angular/core';
import { ProductService } from '../services/product.service';  // NUEVO

@Component({
  selector:    'app-products',
  templateUrl: './products.html',
  styleUrls:   ['./products.css']
})
export class ProductsComponent implements OnInit {

  // Propiedades — igual que en Clase 5
  titulo = 'Proyecto API';
  valor  = '';
  data:    any = [];
  detalle: any = null;

  // Constructor — ahora inyecta el servicio en lugar de HttpClient directo
  constructor(private productService: ProductService) { }

  ngOnInit(): void {
    this.productService.getProducts().subscribe(
      (response) => { this.data = response; },
      (error)    => { console.error('Error:', error); }
    );
  }

  // filtrarCat — ahora usa la API por categoria
  filtrarCat(event: any): void {
    this.valor = event.target.value;

    if (this.valor === 'all') {
      this.productService.getProducts().subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    } else {
      this.productService.getProductsByCategory(this.valor).subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    }
  }

  // filtrarNombre — sigue filtrando el array local
  filtrarNombre(event: any): void {
    const tituloInput = document.getElementById('txtTitle') as HTMLInputElement;
    this.valor = event.target.value;

    if (this.valor === '') {
      this.productService.getProducts().subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    } else {
      this.productService.getProducts().subscribe(
        (response) => {
          const v = this.valor.toLowerCase();
          this.data = (response as any[]).filter(p => p.title.toLowerCase().includes(v));
        },
        (error) => { console.error('Error:', error); }
      );
    }
  }

  // detallePro — igual que en Clase 5
  detallePro(productId: number): void {
    this.productService.getProductById(productId).subscribe(
      (response) => { this.detalle = response; },
      (error)    => { console.error('Error:', error); }
    );
  }
}
El template HTML no cambia nada. La tabla, los filtros y el modal de la Clase 5 siguen funcionando exactamente igual. Solo cambia de donde vienen los datos: antes del array local, ahora de la API.

import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { ProductsComponent } from './products/products';
import { ProductDetailComponent } from './product-detail/product-detail';  // NUEVO

const routes: Routes = [
  { path: '',            redirectTo: '/products', pathMatch: 'full' },
  { path: 'products',    component: ProductsComponent,     title: 'Gestion de Productos' },
  { path: 'product/:id', component: ProductDetailComponent,   title: 'Detalle Producto' },  // NUEVO

  exports: [RouterModule]
})
export class AppRoutingModule { }
Los dos puntos en :id indican un parametro de ruta. Cuando el usuario navega a /product/5, Angular captura 5 como el valor del parametro id. El componente lo lee con ActivatedRoute para hacer la llamada a la API.

Vista de detalle

El componente que lee el :id de la URL y carga el producto desde la API.

Paso 7 product-detail.ts

src/app/product-detail/product-detail.tsTypeScript
import { Component, OnInit } from '@angular/core';
import { ActivatedRoute } from '@angular/router';          // lee parametros de la URL
import { ProductService } from '../services/product.service';

@Component({
  selector:    'app-product-detail',
  templateUrl: './product-detail.html',
  styleUrls:   ['./product-detail.css']
})
export class ProductDetailComponent implements OnInit {

  // Propiedades
  detalle: any     = null;
  cargando: boolean = false;
  error: string     = '';

  constructor(
    private route:          ActivatedRoute,   // para leer el :id de la URL
    private productService: ProductService
  ) { }

  ngOnInit(): void {
    // 1. Leer el parametro :id de la URL
    const id = Number(this.route.snapshot.paramMap.get('id'));

    // 2. Pedir el producto a la API usando el servicio
    this.cargando = true;
    this.productService.getProductById(id).subscribe(
      (response) => {
        this.detalle  = response;
        this.cargando = false;
      },
      (error) => {
        console.error('Error:', error);
        this.error    = 'No se pudo cargar el producto.';
        this.cargando = false;
      }
    );
  }
}
route.snapshot.paramMap.get('id') lee el valor del parametro :id de la URL actual. Si el usuario esta en /product/5, devuelve el string "5". El Number() lo convierte a numero para pasarlo al servicio.

Preguntas frecuentes

Cual es la diferencia entre HttpClient.get() y fetch()?

Funcionalmente hacen lo mismo: una peticion GET HTTP. La diferencia es que HttpClient devuelve un Observable (de RxJS), esta integrado con el sistema de Angular, y permite cancelar peticiones. fetch() devuelve una Promise y es nativo del navegador.

Por que providedIn: 'root' en el servicio?

Le dice a Angular que cree una unica instancia del servicio para toda la aplicacion (singleton). Asi ProductsComponent y ProductDetailComponent comparten la misma instancia del servicio.

Cuando uso routerLink y cuando router.navigate()?

routerLink se usa en el template HTML, en etiquetas <a> o botones. router.navigate() se usa desde el TypeScript, por ejemplo despues de que un formulario se envia correctamente. Los dos logran la misma navegacion.

Clase 7 — lo que se agrega al proyectoTypeScript
// auth.service.ts — maneja el JWT
login(username: string, password: string): Observable<any> {
  return this.http.post('https://fakestoreapi.com/auth/login', { username, password });
}

// auth.interceptor.ts — agrega el token a cada peticion automaticamente
intercept(req: HttpRequest<any>, next: HttpHandler) {
  const token = localStorage.getItem('token');
  if (token) {
    const cloned = req.clone({ setHeaders: { Authorization: `Bearer ${token}` }});
    return next.handle(cloned);
  }
  return next.handle(req);
}

// app-routing-module.ts — la ruta /users queda protegida
{ path: 'users', component: UsersComponent, canActivate: [AuthGuard] }

El concepto clave

Un interceptor es como un filtro: intercepta todas las peticiones HTTP antes de que salgan y les agrega el token. No tienes que tocarlo en cada componente — se configura una vez y funciona en toda la app.
