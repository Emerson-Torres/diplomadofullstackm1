HttpClient

El modulo oficial de Angular para consumir APIs. Mismo concepto que fetch() pero integrado con el sistema de Angular.

Observable vs Promise

La diferencia principal con fetch() es que HttpClient devuelve un Observable en lugar de una Promise. Para este curso son funcionalmente equivalentes:

fetch() — Clases 1 a 5
async function cargar() {
  const res  = await fetch('url');
  const data = await res.json();
  this.data = data;
}
HttpClient — desde Clase 6
ngOnInit(): void {
  this.http.get('url').subscribe(
    (response) => {
      this.data = response;
    }
  );
}
Por que .subscribe()? Un Observable es como una suscripcion a un canal: no llegan los datos hasta que te suscribes. .subscribe(callback) es el equivalente a .then(callback) en Promesas. El callback recibe los datos cuando llegan.

Paso 1 Configurar HttpClient en app-module.ts (sin HttpClientModule)

Desde Angular 19/20, la forma recomendada es configurar HttpClient con provideHttpClient(...) en providers. En proyectos con NgModules no hace falta usar HttpClientModule en imports:

src/app/app-module.ts — forma recomendada en Angular actualTypeScript
import { NgModule, provideBrowserGlobalErrorListeners } from '@angular/core';
import { BrowserModule } from '@angular/platform-browser';
import { FormsModule } from '@angular/forms';
import { provideHttpClient, withInterceptorsFromDi } from '@angular/common/http';

import { AppRoutingModule } from './app-routing-module';
import { App } from './app';
import { Products } from './products/products';
import { ProductCard } from './product-card/product-card';

@NgModule({
  declarations: [
    App,
    Products,
    ProductCard,
  ],
  imports: [
    BrowserModule,
    FormsModule,
    AppRoutingModule,
    // No usar HttpClientModule aqui
  ],
  providers: [
    provideBrowserGlobalErrorListeners(),
    provideHttpClient(withInterceptorsFromDi())
  ],
  bootstrap: [App]
})
export class AppModule { }
Error comun: NullInjectorError: No provider for HttpClient. En esta version, la solucion es revisar que exista provideHttpClient(withInterceptorsFromDi()) dentro del array providers de app-module.ts.
Dato oficial importante: HttpClientModule aparece como deprecated en la API de Angular y recomiendan migrar a provideHttpClient(...). Si usas interceptores funcionales, Angular recomienda withInterceptors(...); si ya tienes interceptores por DI, usa withInterceptorsFromDi().
Extra para Angular moderno: para apps con SSR, la guia oficial recomienda habilitar fetch con provideHttpClient(withFetch()) por rendimiento y compatibilidad.

Servicios

Una clase con @Injectable() que centraliza la logica de negocio. Los componentes lo consumen sin conocer los detalles.

Por que usar un servicio?

Codigo que se vuelve dificil de mantener
// En products.ts
constructor(private http: HttpClient) {}

ngOnInit() {
  this.http.get('...fakestoreapi.com/products')
    .subscribe(r => this.data = r);
}

// En product-detail.ts — repetido
constructor(private http: HttpClient) {}

ngOnInit() {
  this.http.get('...fakestoreapi.com/products/'+id)
    .subscribe(r => this.detalle = r);
}
Como mejorar: centralizar en un servicio
// En product.service.ts — un solo lugar
getProducts() {
  return this.http.get('...fakestoreapi.com/products');
}
getProductById(id) {
  return this.http.get('...fakestoreapi.com/products/'+id);
}

// En cualquier componente — simple y limpio
ngOnInit() {
  this.productService.getProducts()
    .subscribe(r => this.data = r);
}

Paso 2 Generar el servicio

El CLI crea el archivo en la subcarpeta services/. El servicio se genera con providedIn: 'root' — Angular lo registra automaticamente de forma global, sin tocarlo en app-module.ts:

terminal — dentro de mi-tienda/bash
ng generate service services/product.service
# Atajo equivalente:
ng g s services/product.service

# El CLI crea (en Angular 20):
#   src/app/services/product.service.ts
#   src/app/services/product.service.spec.ts  (tests - ignorar por ahora)
#
# Los servicios con providedIn: 'root' NO necesitan registrarse en app-module.ts
# Angular los registra automaticamente de forma global
Por que services/product.service y no solo product.service? La barra / le dice al CLI que cree el archivo dentro de la carpeta services/. Si la carpeta no existe, la crea. Es una convencion para mantener los servicios organizados separados de los componentes.

Paso 3 Escribir product.service.ts

El CLI genera el archivo con la estructura base. Agrega los cuatro metodos que usara la aplicacion:

src/app/services/product.service.tsTypeScript
import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable({
  providedIn: 'root'  // disponible en toda la app sin registrar en app-module.ts
})
export class ProductService {

  private apiUrl = 'https://fakestoreapi.com/products';

  constructor(private http: HttpClient) { }

  getProducts(): Observable<any[]> {
    return this.http.get<any[]>(this.apiUrl);
  }

  getProductById(id: number): Observable<any> {
    return this.http.get<any>(`${this.apiUrl}/${id}`);
  }

  getProductsByCategory(category: string): Observable<any[]> {
    return this.http.get<any[]>(`${this.apiUrl}/category/${category}`);
  }
}
Nota Angular 20: los servicios no cambian su API entre versiones. @Injectable({ providedIn: 'root' }) funciona exactamente igual en Angular 20 que en versiones anteriores. No necesitas standalone: false en servicios — ese decorador solo aplica a componentes.

Paso 4 products.ts actualizado

Los cambios son minimos: se agrega la inyeccion del servicio en el constructor y se actualizan los metodos que usaban el mock. El template products.html no requiere ninguna modificacion.

src/app/products/products.ts — version Clase 6TypeScript
import { Component, OnInit } from '@angular/core';
import { ProductService } from '../services/product.service';  // NUEVO

@Component({
  selector:    'app-products',
  standalone:  false,
  templateUrl: './products.html',
  styleUrl:    './products.css'
})
export class Products implements OnInit {

  // Propiedades — igual que en Clase 5
  titulo   = 'Proyecto API';
  valor    = '';
  busqueda    = '';
  data:    any = [];
  detalle: any = null;

  // Constructor — ahora inyecta el servicio en lugar del HttpClient directo
  constructor(private productService: ProductService) { }

  ngOnInit(): void {
    this.productService.getProducts().subscribe(
      (response) => { this.data = response; },
      (error)    => { console.error('Error:', error); }
    );
  }

  // filtrarCat — ahora llama a la API por categoria
  filtrarCat(event: any): void {
    this.valor = event.target.value;
    if (this.valor === 'all') {
      this.productService.getProducts().subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    } else {
      this.productService.getProductsByCategory(this.valor).subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    }
  }

  // filtrarNombre — ahora filtra sobre los datos ya cargados
  filtrarNombre(event: any): void {
    this.valor = event.target.value;
    if (this.valor === '') {
      this.productService.getProducts().subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    } else {
      this.productService.getProducts().subscribe(
        (response) => {
          const v = this.valor.toLowerCase();
          this.data = (response as any[]).filter(p => p.title.toLowerCase().includes(v));
        },
        (error) => { console.error('Error:', error); }
      );
    }
  }

  // filtrarNombreNgModel — filtra usando la propiedad enlazada con ngModel
  filtrarNombreNgModel(): void {
    this.valor = this.busqueda;
    if (this.valor === '') {
      this.productService.getProducts().subscribe(
        (response) => { this.data = response; },
        (error)    => { console.error('Error:', error); }
      );
    } else {
      this.productService.getProducts().subscribe(
        (response) => {
          const v = this.valor.toLowerCase();
          this.data = (response as any[]).filter(p => p.title.toLowerCase().includes(v));
        },
        (error) => { console.error('Error:', error); }
      );
    }
  }

  // detallePro — ahora llama a la API por id
  detallePro(productId: number): void {
    this.productService.getProductById(productId).subscribe(
      (response) => { this.detalle = response; },
      (error)    => { console.error('Error:', error); }
    );
  }
}
El template products.html no cambia nada. La tabla, los filtros y el modal de la Clase 5 siguen funcionando exactamente igual. Solo cambia de donde vienen los datos: antes del array mock, ahora de la API.
Nota sobre busqueda: filtrarNombre() hace dos llamadas a la API: una para obtener todos los productos y luego filtra en memoria. En produccion esto seria ineficiente para listas grandes, pero para este curso y FakeStoreAPI es suficiente.

import { NgModule } from '@angular/core';
import { RouterModule, Routes } from '@angular/router';
import { Products } from './products/products';
import { ProductDetail } from './product-detail/product-detail';  // NUEVO

const routes: Routes = [
  { path: '',            redirectTo: '/products', pathMatch: 'full' },
  { path: 'products',    component: Products,     title: 'Gestion de Productos' },
  { path: 'product/:id', component: ProductDetail, title: 'Detalle Producto' },  // NUEVO

  // { path: 'login', ... }    — Clase 7
  // { path: 'cart', ... }     — Clase 7

  imports: [RouterModule.forRoot(routes)],
  exports: [RouterModule]

Vista de detalle

El componente que lee el :id de la URL y carga el producto desde la API.

Paso 8 product-detail.ts

src/app/product-detail/product-detail.tsTypeScript
import { Component, OnInit } from '@angular/core';
import { ActivatedRoute } from '@angular/router';          // lee parametros de la URL
import { ProductService } from '../services/product.service';

@Component({
  selector:    'app-product-detail',
  standalone:  false,
  templateUrl: './product-detail.html',
  styleUrl:    './product-detail.css'
})
export class ProductDetail implements OnInit {

  // Propiedades
  detalle:  any     = null;
  cargando: boolean = false;
  error:    string  = '';

  constructor(
    private route:          ActivatedRoute,   // para leer el :id de la URL
    private productService: ProductService
  ) { }

  ngOnInit(): void {
    // 1. Leer el parametro :id de la URL
    const id = Number(this.route.snapshot.paramMap.get('id'));

    // 2. Pedir el producto a la API usando el servicio
    this.cargando = true;
    this.productService.getProductById(id).subscribe(
      (response) => {
        this.detalle  = response;
        this.cargando = false;
      },
      (error) => {
        console.error('Error:', error);
        this.error    = 'No se pudo cargar el producto.';
        this.cargando = false;
      }
    );
  }
}
route.snapshot.paramMap.get('id') lee el valor del parametro :id de la URL actual. Si el usuario esta en /product/5, devuelve el string "5". El Number() lo convierte a numero para pasarlo al servicio.
Nota Angular 20: la clase se llama ProductDetail (sin sufijo Component), el archivo es product-detail.ts (sin .component), y el decorador incluye standalone: false para que pueda declararse en el AppModule.

Errores comunes y sus soluciones

1 NullInjectorError: No provider for HttpClient

Consola del navegador al cargar /products

Solucion: agregar HttpClientModule al array imports (no a declarations) en app-module.ts. Verificar el import arriba: import { HttpClientModule } from '@angular/common/http';

2 La ruta /product/:id muestra pagina en blanco

Navegador — se navega a /product/5 pero no aparece nada
La pagina de detalle esta en blanco
Un error comun es olvidar importar ProductDetail en app-routing-module.ts. Verificar tambien que la ruta este declarada: { path: 'product/:id', component: ProductDetail }. Y que ProductDetail este en declarations de app-module.ts.

3 Cannot read properties of null (reading 'image') en el detalle

Consola del navegador
TypeError: Cannot read properties of null (reading 'image')
Solucion: agregar *ngIf="detalle && !cargando" al contenedor del HTML del detalle. El template intenta renderizar antes de que llegue la respuesta de la API. El *ngIf espera a que detalle tenga valor.

4 Error: 'router-outlet' is not a known element

Consola del navegador / compilacion
'router-outlet' is not a known element
Solucion: AppRoutingModule no esta en el array imports de app-module.ts. Verificar que el modulo de routing sigue importado (venia desde Clase 5).

Preguntas frecuentes

Cual es la diferencia entre HttpClient.get() y fetch()?

Funcionalmente hacen lo mismo: una peticion GET HTTP. La diferencia es que HttpClient devuelve un Observable (de RxJS), esta integrado con Angular, y permite cancelar peticiones. fetch() devuelve una Promise y es nativo del navegador.

Por que providedIn: 'root' en el servicio?

Le dice a Angular que cree una unica instancia del servicio para toda la aplicacion. Asi Products y ProductDetail comparten la misma instancia del servicio sin configuracion adicional.

Cuando uso routerLink y cuando router.navigate()?

routerLink se usa en el template HTML, en etiquetas <a>. router.navigate() se usa desde el TypeScript, por ejemplo despues de que un formulario se envia correctamente. En Clase 7 usaremos router.navigate() despues del login.

// auth.interceptor.ts — agrega el token a cada peticion automaticamente
intercept(req: HttpRequest<any>, next: HttpHandler) {
  const token = localStorage.getItem('token');
  if (token) {
    const cloned = req.clone({ setHeaders: { Authorization: `Bearer ${token}` }});
    return next.handle(cloned);
  }
  return next.handle(req);
}

El concepto clave

Un interceptor es como un filtro que actua en todas las peticiones HTTP antes de que salgan. Se configura una vez en app-module.ts y funciona en toda la app sin tocar cada componente.
