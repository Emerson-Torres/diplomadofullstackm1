TypeScript Esencial

No es un lenguaje nuevo. Es JavaScript con superpoderes. Aprenderás lo mínimo necesario para que Angular tenga sentido cuando lo veas por primera vez.

2h efectivas Tipado estático Sin tsconfig
Mensaje clave de esta clase: TypeScript no es difícil. Ya sabes JavaScript — TypeScript solo agrega anotaciones de tipo encima. Todo lo que TS compila produce JS normal. Angular lo exige porque los tipos permiten que el editor te ayude a no romper cosas.
¿Qué problema resuelve?

Los errores de typo (data.titlee) que en JS solo aparecen en producción, en TS los ve el editor mientras escribes.

Lo que aprenderás

Tipos básicos, interfaces para modelar la API de FakeStore, funciones tipadas, y fetch con Promise<T>.

Lo que NO veremos hoy

tsconfig.json, decoradores, genéricos avanzados, namespaces, ni nada que no necesites hasta Angular. Hoy es lo mínimo viable.

El problema que TypeScript resuelve

Un bug que JavaScript no te avisa y TypeScript sí. Antes de aprender la sintaxis, hay que entender el por qué.

El bug silencioso de JavaScript

Este código se ve razonable. Corre sin errores de sintaxis. Pruébalo:

bug-silencioso.jsJavaScript 
async function mostrarProducto() {
  const res  = await fetch("https://fakestoreapi.com/products/1");
  const data = await res.json();

  document.getElementById("titulo").textContent = "Título: " + data.titlee;   // ← typo
  document.getElementById("precio").textContent = "Price: $" + data.prce;     // ← typo
  document.getElementById("cat").textContent    = data.categorya();             // ← no es función
}
mostrarProducto();

El mismo código en TypeScript

TypeScript detecta los tres errores mientras escribes, sin necesidad de ejecutar nada:

JavaScript vs TypeScript — la relación real

JavaScript
  • Tipado dinámico — los tipos se resuelven en ejecución
  • Los errores de tipo aparecen cuando el código corre
  • El navegador lo entiende directamente
  • Más flexible pero más peligroso
TypeScript
  • Tipado estático — los tipos se verifican antes de ejecutar
  • Los errores aparecen en el editor, mientras escribes
  • Compila a JavaScript — el navegador nunca ve TS
  • Más verboso pero mucho más seguro
TypeScript es un superset de JavaScript. Todo el JS que escribiste en las clases 0–3 es TypeScript válido. No empiezas desde cero — solo agregas anotaciones de tipo encima.

Antes de compilar: setup inicial (equipo desde 0)

¿Qué es Node.js?

Es un entorno que ejecuta JavaScript fuera del navegador (en tu computadora). Permite usar herramientas como npm y tsc desde la terminal.

¿Cómo funciona?

Node usa el motor V8 para ejecutar JS. npm instala paquetes globales o locales. Cuando ejecutas npm install -g typescript, el comando tsc queda disponible en tu terminal.

¿Por qué es relevante en este curso? Porque todo el flujo de TypeScript depende de Node: instalar el compilador, compilar .ts a .js, y más adelante levantar proyectos con Angular CLI. Sin Node, no hay npm, no hay tsc, y en general no puedes ejecutar el pipeline del curso.
¿Qué versión de Node.js instalar?
Instala Node.js v22.x LTS. Es la versión compatible con Angular 19 (que usaremos desde la Clase 5).
No instales Node v24 aunque aparezca como LTS en la página oficial — Angular 19 no la soporta.

Descarga: nodejs.org/en/download → busca la última 22.x LTS.

Cómo ejecutarlo: abre index.html en el navegador después de compilar. Si todo está correcto, verás el mensaje en pantalla y también en consola: Hola mundo desde TypeScript.
Ojo: en el HTML debes enlazar el archivo así: <script type="module" src="app.js"></script>.
¿Por qué agregamos export {} si no estamos exportando nada?
Porque es la forma más simple de decirle a TypeScript: "este archivo es un módulo". Al hacerlo, variables como mensaje dejan de vivir en el ámbito global y quedan encerradas dentro del archivo.

¿Qué problema evita? Errores muy comunes como: Cannot redeclare block-scoped variable 'mensaje'.
Eso pasa cuando TypeScript interpreta varios archivos como scripts globales y mezcla sus variables. Con export {}, cada archivo queda aislado y ese choque de nombres desaparece.

Pero hay una consecuencia importante: si el archivo compilado contiene export {}, entonces el navegador debe cargar app.js como módulo. Si lo cargas como script normal, verás este error:
Uncaught SyntaxError: Unexpected token 'export'.
Solución: en el HTML usa <script type="module" src="app.js"></script>.

Tipos básicos

La sintaxis central: variable: tipo. Nada más.

Tabla rápida de tipos de datos

Según la documentación oficial de TypeScript, estos son los tipos cotidianos que más usarás:

Tipo ¿Para qué sirve? Ejemplo
string Texto let nombre: string = "Ana"
number Cualquier número normal: entero o decimal let precio: number = 19.99
boolean Verdadero o falso let activo: boolean = true
string[] Arreglo de textos let tags: string[] = ["ts", "js"]
number[] Arreglo de números let notas: number[] = [4.5, 5.0]
string | number Unión: puede ser uno u otro let id: string | number = 10
null / undefined Ausencia de valor let respuesta: string | null = null
any Desactiva el chequeo de tipos let dato: any = "hola"
bigint Enteros muy grandes let grande: bigint = 100n
Pregunta frecuente: ¿y decimal, float, double o int?
En TypeScript no existen como tipos separados. Igual que en JavaScript, todos los números normales usan number.
Eso incluye enteros como 10, decimales como 19.99, y valores que en otros lenguajes llamarías float o double.
Regla práctica: si es un número común, usa number; si es un entero gigantesco, usa bigint.
Importante: escribe siempre string, number y boolean en minúscula. Es la forma recomendada por la documentación oficial.

Anotar variables

En TypeScript escribes el tipo después del nombre de la variable con :. Eso es todo el "misterio":

tipos-basicos.tsTypeScript
// ── string ────────────────────────────────────────────────────
let nombre: string  = "María";
let titulo: string  = "Fjallraven Backpack";

nombre = "Carlos";         // ✓ OK — sigue siendo string
nombre = 42;              // ✗ ERROR: Type 'number' is not assignable to type 'string'

// ── number ────────────────────────────────────────────────────
let precio: number  = 109.95;
let cantidad: number = 3;
let total: number   = precio * cantidad;  // → 329.85

// ── boolean ───────────────────────────────────────────────────
let activo: boolean    = true;
let enCarrito: boolean = false;

// ── Arrays ────────────────────────────────────────────────────
let categorias: string[]  = ["electronics", "jewelery", "men's clothing"];
let precios: number[]     = [29.99, 52.50, 109.95];

categorias.push("women's clothing");  // ✓ OK
categorias.push(42);                  // ✗ ERROR: number no es string

// ── any — la trampa ───────────────────────────────────────────
let cualquierCosa: any = "texto";
cualquierCosa = 42;        // ✓ compila — any desactiva el chequeo
cualquierCosa = true;      // ✓ también compila
// ⚠ Usar "any" es rendirse a TypeScript — úsalo solo en casos muy específicos

Inferencia de tipos — TypeScript suele adivinar solo

Si asignas un valor en la misma línea en que declaras la variable, TypeScript infiere el tipo automáticamente. No siempre necesitas escribirlo:

inferencia.tsTypeScript
// Con anotación explícita
let precio: number = 29.99;

// Sin anotación — TypeScript infiere "number" igual
let precio2 = 29.99;   // TypeScript ya sabe que es number
precio2 = "caro";     // ✗ ERROR — ya sabe que debería ser number

// Con const, siempre infiere el valor exacto (literal type)
const API = "https://fakestoreapi.com";
// TypeScript infiere: const API: "https://fakestoreapi.com" (valor exacto, no solo string)
API = "https://otra-api.com"; // ✗ ERROR: no puedes reasignar una constante

// Ejemplo donde también falla por literal type:
function soloFakeStore(url: "https://fakestoreapi.com") { }
soloFakeStore(API);                          // ✓ OK
soloFakeStore("https://otra-api.com");       // ✗ ERROR: no coincide el literal esperado

// Cuándo SÍ conviene anotar explícitamente:
let producto: Product;      // variable declarada sin valor inicial
let resultado: string | null; // puede ser string o null
Regla práctica: Deja que TypeScript infiera cuando asignas un valor simple (number, string, boolean). Anota explícitamente cuando el tipo es complejo (Product, Product[]), cuando declaras sin valor, o cuando la función puede retornar dos cosas distintas.

undefined y null — el territorio peligroso

undefined-null.tsTypeScript 
// document.getElementById puede devolver null si el elemento no existe
const titulo = document.getElementById("titulo");
titulo.textContent = "Hola";  // ✗ ERROR: titulo puede ser null

// Solución 1: el operador ! (non-null assertion) — "yo sé que existe"
document.getElementById("titulo")!.textContent = "Hola";
// ⚠ Si te equivocas en el id, el ! oculta el null y explota en runtime:
document.getElementById("titluo")!.textContent = "Hola"; // TypeError: Cannot set properties of null

// Solución 2: optional chaining ?. — "solo si existe"
document.getElementById("titulo")?.textContent;
// ✓ Si no existe, NO lanza error: la expresión se corta y no ejecuta textContent

// Solución 3: verificar con if antes
const el = document.getElementById("titulo");
if (el) { el.textContent = "Hola"; }  // ✓ dentro del if, TS sabe que no es null

// Union types — puede ser una cosa O otra
let valor: string | null    = null;
let id:    number | string  = 1;
id = "abc";   // también válido

Interfaces — Modelar los datos de la API

Una interface es un contrato: define qué campos tiene un objeto y de qué tipo es cada uno.

De objeto JS a interface TypeScript

Mira la respuesta de FakeStore API. Ya conoces este objeto de las clases anteriores:

Lo que devuelve la API (JSON)
{
  "id":          1,
  "title":       "Fjallraven Backpack",
  "price":       109.95,
  "category":    "men's clothing",
  "description": "Your perfect pack...",
  "image":       "https://fakestoreapi.com/img/...",
  "rating": {
    "rate":  3.9,
    "count": 120
  }
}
La interface TypeScript
interface Rating {
  rate:  number;
  count: number;
}

interface Product {
  id:          number;
  title:       string;
  price:       number;
  category:    string;
  description: string;
  image:       string;
  rating:      Rating;
}
El proceso de trabajo real: Abres Postman, haces un GET a la API, miras la respuesta JSON, y traduces cada campo a la interface. Es mecánico. El editor ya hará el resto.

Usar la interface

usar-interface.tsTypeScript 
interface Product {
  id:       number;
  title:    string;
  price:    number;
  category: string;
  image:    string;
  rating:   { rate: number; count: number };
}

// ── Variable tipada ───────────────────────────────────────────
const producto: Product = {
  id:       1,
  title:    "Fjallraven Backpack",
  price:    109.95,
  category: "men's clothing",
  image:    "https://fakestoreapi.com/img/...",
  rating:   { rate: 3.9, count: 120 }
};

// Ahora el editor tiene autocomplete completo:
producto.title        // → "Fjallraven Backpack"
producto.rating.rate  // → 3.9
producto.titlee       // ✗ ERROR: Property 'titlee' does not exist

// ── Array de interfaces ───────────────────────────────────────
const productos: Product[] = [];  // array vacío tipado
productos.push(producto);          // ✓ OK — producto es un Product

// ── Campo opcional con ? ──────────────────────────────────────
interface CartItem {
  product:  Product;
  quantity: number;
  note?:    string;   // opcional — puede o no estar
}

Funciones tipadas

Anotar los parámetros y el valor de retorno. El editor te avisa si usas mal la función.

Anatomía de una función TypeScript

funciones.tsTypeScript
// ── Función simple tipada ─────────────────────────────────────
function saludar(nombre: string): string {
  return `Hola, ${nombre}!`;
}
saludar("María");  // ✓ → "Hola, María!"
saludar(42);       // ✗ ERROR: Argument of type 'number' is not assignable to 'string'

// ── void: la función no retorna nada útil ─────────────────────
function mostrarProducto(producto: Product): void {
  document.getElementById("titulo")!.textContent = producto.title;
  document.getElementById("precio")!.textContent = "$" + producto.price;
  // No retorna nada — como void en Java/C#
}

// ── Parámetros opcionales ─────────────────────────────────────
function formatPrecio(precio: number, simbolo?: string): string {
  const s = simbolo ?? "$";  // ?? = "si es undefined, usa este valor"
  return `${s}${precio.toFixed(2)}`;
}
formatPrecio(29.99);        // → "$29.99"
formatPrecio(29.99, "€");  // → "€29.99"

// ── Arrow function tipada ─────────────────────────────────────
// Esta función RECIBE un arreglo de productos y una categoría
// y RETORNA un NUEVO arreglo solo con los productos que pertenecen a esa categoría.
const filtrarPorCategoria = (
  productos: Product[],
  categoria: string
): Product[] => {
  return productos.filter(p => p.category === categoria);
};

// Ejemplos:
filtrarPorCategoria(productos, "electronics");
// → retorna solo los productos de electrónica
filtrarPorCategoria(productos, "jewelery");
// → retorna solo los productos de joyería

// ── Función que recibe callback ───────────────────────────────
// Un callback es simplemente una función que se le pasa a otra función
// para que la ejecute después, normalmente una vez por cada elemento.
function procesarProductos(
  productos: Product[],
  callback: (p: Product) => void
): void {
  productos.forEach(callback);
}

// Ejemplo 1: mostrar el título de cada producto
procesarProductos(productos, p => {
  console.log(p.title);
});
// → imprime uno por uno los títulos

// Ejemplo 2: mostrar el precio de cada producto
procesarProductos(productos, p => {
  console.log("$" + p.price);
});
// → imprime uno por uno los precios

fetch() con tipos — Promise<T>

Combinar lo que ya sabes hacer (fetch + async/await) con lo que aprendiste hoy (interfaces).

fetch tipado paso a paso

fetch-tipado.tsTypeScript
import { Product } from "./models";

// ── Un solo producto ──────────────────────────────────────────
async function getProducto(id: number): Promise<Product> {
  const res  = await fetch(`https://fakestoreapi.com/products/${id}`);
  const data: Product = await res.json();
  return data;
}

// ── Todos los productos ───────────────────────────────────────
async function getProductos(limit: number = 10): Promise<Product[]> {
  const res  = await fetch(`https://fakestoreapi.com/products?limit=${limit}`);
  const data: Product[] = await res.json();
  return data;
}

// ── Con manejo de errores ─────────────────────────────────────
async function getProductosSeguro(): Promise<Product[]> {
  try {
    const res = await fetch("https://fakestoreapi.com/products?limit=6");

    // Verificar que la respuesta fue exitosa
    if (!res.ok) {
      throw new Error(`HTTP error: ${res.status}`);
    }

    const productos: Product[] = await res.json();
    return productos;

  } catch (error: unknown) {
    // "unknown" es más seguro que "any" para errores
    if (error instanceof Error) {
      console.error("Error al cargar productos:", error.message);
    }
    return [];  // retorna array vacío en caso de error
  }
}

// ── Usar la función ───────────────────────────────────────────
async function iniciar(): Promise<void> {
  const productos = await getProductos(6);
  // ↑ TypeScript sabe que "productos" es Product[]

  productos.forEach(p => {
    console.log(p.title);   // autocomplete ✓
    console.log(p.price);   // autocomplete ✓
    console.log(p.titlee);  // ✗ ERROR inmediato
  });
}
iniciar();

function toggleFavorito(id: number): void {

Preguntas frecuentes de esta clase

¿Tengo que anotar el tipo de TODAS las variables?

No. Si asignas un valor en la misma línea, TypeScript infiere el tipo. Anota explícitamente cuando el tipo no es obvio: Product, Product[], retornos de funciones.

¿Puedo usar any cuando no sé el tipo?

Técnicamente sí, pero es rendirse. Es como decirle a TS "no me ayudes aquí". Prefiere unknown para errores, o define la interface correctamente.

¿La interface tiene que coincidir exactamente con el JSON?

No al 100%. Puedes poner solo los campos que vas a usar. Si el JSON tiene más campos, TypeScript no se queja — solo marca error si usas un campo que no declaraste en la interface.

¿Por qué Angular no usa tsc directamente?

Angular CLI usa tsc internamente con una configuración especial en tsconfig.json. Cuando corres ng serve, el CLI compila TS automáticamente en background.

El insight clave

Angular no es un lenguaje nuevo. Es TypeScript dentro de una estructura llamada componente. Ya sabes TypeScript — Angular solo te enseña dónde poner ese código.
