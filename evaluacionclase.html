Evaluacion Final — Modulo 1

Tienda de Recetas con Angular

Aplicaras todo lo visto en el modulo construyendo una aplicacion Angular completa conectada a una API diferente. El objetivo no es repetir la tienda de ropa — es demostrar que entiendes los conceptos y sabes aplicarlos en un contexto nuevo.

5 dias Individual 100 puntos DummyJSON API
Antes de comenzar: crea un proyecto Angular 20 nuevo. No copies el proyecto de las clases. La evaluacion mide si puedes aplicar los mismos conceptos en una base limpia.
crear el proyecto nuevobash
ng new mi-recetario --routing --style=css
cd mi-recetario
ng serve
Autenticacion real

Login con credenciales de DummyJSON. Token JWT real almacenado en localStorage. Rutas protegidas con AuthGuard.

Lista de favoritos

En lugar de un carrito de compras, el usuario guardara recetas favoritas. La logica de persistencia y BehaviorSubject es equivalente.

Busqueda y filtros

Filtrar recetas por cocina (cuisine) y buscar por nombre. La logica de filtrado viene de la Clase 5 y 6 — se aplica aqui con datos distintos.

Contexto de la aplicacion

Construiras RecetApp: una aplicacion donde los usuarios pueden explorar recetas de cocina. Cualquier visitante puede ver el listado, pero para guardar favoritos y ver su perfil, debe iniciar sesion. Los favoritos de cada usuario se guardan en localStorage y persisten entre sesiones.

La logica de negocio que aplicas es:

  • Un usuario no logueado puede ver recetas y su detalle, pero no puede agregar favoritos.
  • Un usuario logueado ve el boton "Agregar a favoritos" y tiene acceso a /favoritos y a /perfil.
  • Al cerrar sesion, los favoritos se conservan en localStorage. Al volver a ingresar con el mismo usuario, los encuentra tal como los dejo.
  • Si dos usuarios usan el mismo navegador, cada uno tiene su propia lista de favoritos separada.
Por que es diferente al proyecto de clase: las recetas tienen campos distintos (cuisine, mealType, ingredients, instructions, rating). La vista de detalle mostrara ingredientes en lista y los pasos de preparacion. No es copiar y pegar — hay que adaptar.

La API: DummyJSON

dummyjson.com es una API REST publica de datos mock. Tiene autenticacion JWT real, usuarios, productos y recetas. No necesita registro ni API key.

Endpoints que usaras

Metodo Endpoint Descripcion Uso en el proyecto

GET /auth/me Devuelve datos del usuario autenticado. Requiere el token en el header. perfil/perfil.ts

Credenciales de prueba: username emilys / password emilyspass. El endpoint POST /auth/login devuelve un token JWT real que el interceptor agregara a las peticiones siguientes.

A diferencia de la Clase 7, la respuesta del login ya incluye los datos del usuario. No es necesario hacer el GET a /users primero. Guarda directamente currentUser (con id, username, firstName) y el token en localStorage.

Logica clave a implementar

Las partes que requieren razonamiento propio. No se pueden copiar directamente de la clase — hay que adaptarlas.

auth.service.ts — login simplificado

En la Clase 7 el login hacia primero un GET a /users para validar y luego un POST a /auth/login para obtener el token. En DummyJSON el POST /auth/login ya devuelve los datos del usuario junto con el token, asi que el flujo es mas directo:

pista — flujo de login en auth.service.tsTypeScript
// El login en DummyJSON es mas directo que en FakeStoreAPI:
// No necesitas GET /users primero

login(username: string, password: string): Observable<any> {
  return this.http.post<any>('https://dummyjson.com/auth/login', {
    username,
    password,
    expiresInMins: 60   // DummyJSON acepta este parametro opcional
  });
}

// En login.ts — dentro del subscribe:
(response) => {
  const session = {
    id:        response.id,
    username:  response.username,
    firstName: response.firstName
  };
  localStorage.setItem('currentUser', JSON.stringify(session));
  localStorage.setItem('token', response.token);
  // Luego: loadFavoritosForCurrentUser() y navegar a /recipes
}

favoritos.service.ts — persistencia por usuario

Es equivalente al CartService de la Clase 7 pero con recetas. La clave en localStorage debe incluir el userId para separar por usuario:

pista — estructura de favoritos.service.tsTypeScript
export class FavoritosService {

  private favSubject = new BehaviorSubject<any[]>([]);
  favoritos$ = this.favSubject.asObservable();

  private getUserId(): number | null {
    const raw = localStorage.getItem('currentUser');
    return raw ? JSON.parse(raw).id : null;
  }

  loadFavoritosForCurrentUser(): void {
    const userId = this.getUserId();
    if (!userId) { this.favSubject.next([]); return; }
    const saved = localStorage.getItem(`favoritos_${userId}`);
    this.favSubject.next(saved ? JSON.parse(saved) : []);
  }

  esFavorito(recipeId: number): boolean {
    // Verifica si la receta ya esta en la lista del usuario actual
    return this.favSubject.getValue().some(r => r.id === recipeId);
  }

  toggleFavorito(recipe: any): void {
    // Si ya esta, lo quita. Si no, lo agrega.
    // Completa esta logica: usa esFavorito(), filter() o push()
    // y guarda en localStorage["favoritos_userId"]
  }

  clearInMemory(): void {
    // Limpia la vista pero NO el localStorage
    this.favSubject.next([]);
  }
}
Diferencia con el CartService de clase: en lugar de addToCart() y removeFromCart(), aqui tienes un solo toggleFavorito() que decide si agrega o quita. La logica del toggle es parte de lo que debes implementar.

recipe-card.ts — boton condicional

El componente hijo necesita saber si el usuario esta logueado y si esa receta ya es favorita. Tiene que inyectar ambos servicios:

pista — recipe-card.tsTypeScript
export class RecipeCard {
  @Input() recipe: any = null;

  constructor(
    public  authService:      AuthService,
    public  favoritosService: FavoritosService
  ) { }

  toggle(): void {
    if (this.recipe) {
      this.favoritosService.toggleFavorito(this.recipe);
    }
  }
}

Y en el template recipe-card.html:

pista — recipe-card.html — boton condicionalHTML
<!-- Solo visible si el usuario tiene sesion -->
<button *ngIf="authService.isLoggedIn()"
        class="btn btn-sm"
        [class.btn-danger]="favoritosService.esFavorito(recipe?.id)"
        [class.btn-outline-danger]="!favoritosService.esFavorito(recipe?.id)"
        (click)="toggle()">
  <i class="bi bi-heart-fill me-1"></i>
  {{favoritosService.esFavorito(recipe?.id) ? 'Quitar' : 'Favorito'}}
</button>
[class.btn-danger]: esta es una forma de aplicar clases CSS de forma condicional en Angular. Si la expresion es true, agrega la clase. Si es false, la quita. El boton cambia de apariencia automaticamente cuando el estado de favoritos cambia.

app.ts — logout correcto

El logout debe limpiar la vista del contador pero sin borrar el localStorage. La misma logica de la Clase 7:

pista — app.ts — metodo logoutTypeScript
logout(): void {
  this.authService.logout();             // elimina token y currentUser del localStorage
  this.favoritosService.clearInMemory(); // resetea el BehaviorSubject a [] (sin tocar localStorage)
  this.router.navigate(['/login']);
}

Preguntas frecuentes de evaluacion

Puedo usar la misma logica del interceptor y el guard de clase?

Si. El interceptor y el guard son patrones estandar — la logica es practicamente identica. Lo que se evalua es que los entiendas y los implementes correctamente en el proyecto nuevo, con los imports y archivos correctos.

La API de DummyJSON a veces es lenta, afecta la evaluacion?

No. Si la API responde lento, agrega un spinner de carga con *ngIf="cargando" — es buena practica y suma. Lo que se evalua es que la peticion HTTP sea correcta y que la vista se actualice cuando lleguen los datos.

El boton de favoritos debe estar en la tarjeta o en el detalle, o en ambos?

En ambos para el puntaje completo. En la lista (recipe-card.html) y en la vista de detalle (recipe-detail.html). Ambos llaman a toggleFavorito() del mismo servicio, asi que el estado es consistente.

Que pasa si no llego a completar todos los requerimientos?

Se evalua lo que funciona. Un proyecto que completa bien el nivel base y el nivel medio (60 pts) con partes del avanzado (algunos de los 30 pts) es una entrega solida. El README donde explicas que completaste y que no ayuda a entender el alcance de tu trabajo.
