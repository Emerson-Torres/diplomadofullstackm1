Por que Angular?

Todo lo que aprendiste en las clases anteriores era el "por que". Angular es el "para que".

La evolucion que has visto en este modulo

1
JS + fetch (Clase 1-2)
2
jQuery + AJAX (Clase 3)
3
TypeScript (Clase 4)
4
Angular (Clases 5-7)

Cada paso resolvio un problema del anterior. Angular resuelve el problema que TypeScript solo no puede: organizar una aplicacion grande de forma sostenible.

El problema que Angular resuelve

Con lo que sabes hasta ahora, una tienda con 10 paginas y datos compartidos puede convertirse en esto:

codigo-sin-framework.js - lo que termina pasando
// archivo-1.js - carga productos
async function cargarProductos() { /* fetch... */ }

// archivo-2.js - muestra carrito (necesita los mismos datos)
let carrito = JSON.parse(localStorage.getItem("cart"));
//  Sincronizar manualmente entre archivos

// archivo-3.js - navbar (necesita el contador del carrito)
document.getElementById("contador").textContent = carrito.length;
//  Actualizar el DOM manualmente en cada cambio

// Resultado: codigo dificil de mantener, estado duplicado
// y un bug que arreglas en un lugar y aparece en otro.

Lo que Angular agrega encima de TypeScript

Sin Angular
  • Actualizas el DOM manualmente
  • Cada archivo de JS es independiente
  • Compartir datos entre "paginas" es manual
  • Las rutas las manejas tu con location.href
  • Sin convenciones - cada desarrollador hace lo suyo
Con Angular
  • El DOM se actualiza automaticamente cuando cambian los datos
  • Componentes: cada pieza de UI en su propio archivo organizado
  • Servicios: datos compartidos entre componentes sin codigo repetido
  • Router: rutas declarativas /products, /product/:id
  • Convenciones estrictas - mismo patron en todo el equipo
La diferencia fundamental: en JS puro manipulas el DOM tu mismo. En Angular describes como debe verse el DOM segun el estado de los datos - y Angular se encarga del resto. {{ titulo }} en el HTML siempre muestra el valor actual de titulo en el TypeScript, sin que tengas que hacer nada mas.

Instalacion y Setup

De cero a localhost:4200 corriendo. Comandos para Windows, Mac y Linux.

¿Por qué usamos Angular 20 y no la versión más nueva?

Angular evoluciona rápido, pero para este curso buscamos una versión moderna, estable y muy bien documentada. Angular 20 ofrece justo ese equilibrio: ya incluye las mejoras actuales del framework sin obligarnos a seguir cambios extra de la versión más reciente.

Criterio Angular 20 Versión más reciente
Estabilidad Madura, sólida y lista para producción. Puede traer cambios nuevos que todavía no ves en todos los cursos o equipos.
Documentación Amplia, actualizada y fácil de contrastar con ejemplos reales. A veces cambia más rápido y obliga a reaprender detalles menores.
Aprendizaje Perfecta para entender componentes, servicios, rutas y estado sin ruido adicional. Puede introducir novedades que distraen del objetivo principal del módulo.
La verdad simple: componentes, binding, routing y servicios siguen el mismo modelo mental. Usamos Angular 20 porque es una base actual, profesional y suficientemente estable para aprender bien y luego trabajar con confianza.

¿Y por qué módulos tradicionales, no Standalone Components?

Estas dos decisiones van juntas: elegimos Angular 20 como versión base, y dentro de 20 mantenemos módulos tradicionales para que el flujo del curso sea más claro. Angular 20 soporta tanto standalone components como NgModule; aquí usamos módulos porque hacen más visible cómo se conecta toda la aplicación paso a paso.

Arquitectura modular

Organiza el código en módulos independientes (Productos, Usuarios, Carrito). Cuando el proyecto crezca, cada módulo se puede reutilizar y mantener por separado.

Lazy loading

Carga módulos solo cuando se necesitan. Si un usuario nunca entra al panel de administración, ese código no se descarga. El proyecto carga más rápido.

Estándar de la industria

La mayoría de proyectos en producción usan NgModule. Si buscas trabajo, es lo que verás.

Más explícito

Tienes un solo lugar (app-module.ts) donde registras qué servicios usa toda la aplicación. Así todos los componentes comparten la misma instancia del carrito, del servicio de productos, etc.

Comando que usamos en el curso para crear el proyecto con Angular 20 y módulos tradicionales: ng new mi-tienda --standalone false --routing true --style css

Configuracion del entorno con VS Code

Dos maneras de ejecutar Angular: la rapida en terminal y la profesional con Run and Debug.

Dos formas de ejecutar Angular

Cuando trabajas con Angular puedes levantar tu proyecto de dos maneras. Ambas sirven, pero no ofrecen la misma experiencia cuando necesitas depurar errores reales.

Forma Como se usa Resultado en clase o trabajo
❌ Manual por terminal ng serve en la consola Levanta el proyecto, pero la depuracion queda separada del editor.
✅ Profesional con VS Code Run and Debug con Ctrl + Shift + D Arranca Angular y conecta el navegador al depurador del editor.
Comparacion ❌ Terminal manual ✅ Run and Debug
Breakpoints No quedan conectados al flujo de debug de VS Code. Puedes poner breakpoints directamente en archivos .ts.
Inspeccion Debes usar console.log() o DevTools manualmente. Inspeccionas variables, call stack y watchers en tiempo real.
Servidor Queda corriendo aparte y a veces olvidas detenerlo. Se integra con la sesion de debug y se controla mejor.
Errores comunes Terminal desconectada, puertos ocupados, navegador sin attach. Configuracion persistente y repetible para toda la clase o equipo.
Recomendacion profesional: usa Run and Debug como flujo principal. La terminal manual sirve para salir del paso; la depuracion integrada sirve para entender y resolver bugs.

Configuracion Que ejecuta Para que te sirve como estudiante

Error comun de PowerShell con Angular CLI

Error comun:
ng : No se puede cargar el archivo ... porque la ejecucion de scripts esta deshabilitada en este sistema.

Por que ocurre: PowerShell tiene politicas de restriccion para ejecutar scripts. El CMD no tiene esta restriccion por defecto.

Soluciones:

Opcion 1 - temporal por sesionpowershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass -Force
Opcion 2 - permanente recomendadapowershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
Opcion 3: si no quieres cambiar la politica de PowerShell, usa CMD en lugar de PowerShell para ejecutar ng y npm.

Por que Run and Debug es mejor que la terminal manual

  • El breakpoint se mantiene aunque recargues la pagina.
  • Puedes inspeccionar variables en tiempo real sin llenar el codigo de console.log().
  • El servidor se detiene automaticamente al terminar la sesion de depuracion.
  • La configuracion se comparte con el equipo mediante .vscode/launch.json.

Componentes

La unidad basica de Angular. Todo en Angular es un componente.

Que es un componente?

Un componente es una clase TypeScript decorada con @Component que controla un pedazo de la interfaz. Cada componente tiene 3 archivos:

.ts - la logica

Las propiedades (titulo, data), los metodos (filtrarCat(), ngOnInit()) y las dependencias inyectadas.

.html - el template

El HTML con sintaxis Angular: {{ }}, *ngFor, (click), [src]. Se actualiza automaticamente cuando cambian los datos.

.css - los estilos

CSS con scope: solo afecta a ese componente, no al resto de la app. No hay conflictos de clases.

Por que agregamos standalone: false?
En Angular moderno, los componentes son standalone por defecto. Pero en este curso estamos usando arquitectura con NgModule (porque facilita entender registro, imports y flujo tradicional). Para que un componente pueda ir en declarations de AppModule, debe estar marcado con standalone: false.

Resumen practico: si usas modulos tradicionales, pon standalone: false. Si omites esa linea, Angular puede tratar el componente como standalone y te dara conflictos al declararlo en el modulo.
Referencia oficial (Angular.dev): la guia de Components explica que en versiones actuales los componentes son standalone por defecto, y la guia de NgModules indica que para declararlos en un modulo deben marcarse con standalone: false. Components - Using components | NgModules - Declarations

Data Binding

Las 4 formas de conectar el TypeScript con el HTML. Es el nucleo de Angular.

Las 4 formas de binding

{{ }} Interpolacion

Muestra el valor de una propiedad del TS en el HTML. Solo lectura - el HTML no puede cambiar el TS.

{{ titulo }} "Proyecto API"
[propiedad] Property Binding

Asigna un valor del TS a una propiedad del elemento HTML. Para atributos dinamicos.

[src]="product.image" muestra la imagen
(evento) Event Binding

Ejecuta un metodo del TS cuando ocurre un evento en el HTML (click, keyup, change...).

(click)="detallePro(product.id)"
[(ngModel)] Two-way Binding

TS HTML y HTML TS simultaneamente. Para formularios. Con [(ngModel)] no necesitas (keyup) para capturar texto. FormsModule es el modulo de Angular Forms que habilita [(ngModel)]; se importa en app-module.ts y se agrega en imports.

[(ngModel)]="busqueda"

ngFor - Renderizar listas

La directiva que convierte un array TypeScript en filas de una tabla. La usaras en absolutamente todos los proyectos Angular.

Sintaxis de ngFor

ngFor - todas las formas que necesitas saberHTML
<!-- Forma basica - itera "data" del componente TS -->
<tr *ngFor="let product of data">
  <td>{{product.id}}</td>
  <td>{{product.title}}</td>
</tr>

<!-- Con indice - util para numerar filas -->
<tr *ngFor="let product of data; let i = index">
  <td>{{i + 1}}</td>
  <td>{{product.title}}</td>
</tr>
El asterisco * es obligatorio. ngFor (sin asterisco) no funciona - Angular lanza un error. El * indica que es una directiva estructural que modifica el DOM.

*ngIf - mostrar/ocultar segun condicion

*ngIf en el templateHTML
<!-- Se muestra SOLO si detalle no es null -->
<div *ngIf="detalle" class="alert alert-info">
  Seleccionado: {{detalle.title}}
</div>

<!-- Con else -->
<div *ngIf="data.length > 0; else sinResultados">
  <table>...</table>
</div>
<ng-template #sinResultados>
  <p>No hay productos que coincidan con la busqueda.</p>
</ng-template>

Que esta mal en este intento de mejora

Esta idea parece natural al principio, pero mezcla responsabilidades y puede confundir mucho al alumno:

products.html - intento que parece correcto pero no lo esHTML
<tr *ngFor="let product of data">
  <app-product-card
    [product]="product"
    (click)="detallePro(product.id)"
  ></app-product-card>
</tr>
Problema Por que confunde
(click) en <app-product-card> No es un evento propio del componente hijo. Es solo un click DOM que se propaga desde algun elemento interno. Eso no define una API clara entre padre e hijo.
Input y click mezclados Input() sirve para enviar datos del padre al hijo. Si el hijo quiere avisar algo al padre, la herramienta correcta es Output().
<app-product-card> dentro de <tr> Una fila de tabla debe mantener estructura HTML valida. Angular permite selectores por atributo, y en este caso conviene montar el componente sobre el <tr> nativo.
Documentacion oficial: Angular documenta que Input se usa para pasar datos a un componente hijo y que los eventos personalizados deben salir mediante Output. Tambien documenta que un componente puede usar selectores por atributo cuando quieres aprovechar un elemento HTML nativo como <tr>. Inputs | Outputs | Attribute selectors

Paso correcto: Input para bajar datos y Output para subir eventos

La refactorizacion correcta queda asi: el padre envia un producto al hijo con [product], y el hijo emite un evento propio cuando el usuario pulsa Ver detalle. Asi cada componente tiene una responsabilidad clara.

src/app/product-card/product-card.tsTypeScript
import { Component, EventEmitter, Input, Output } from '@angular/core';

@Component({
  selector: 'tr[app-product-card]',
  standalone: false,
  templateUrl: './product-card.html',
  styleUrl: './product-card.css',
})
export class ProductCard {

  @Input() product: any = null;
  @Output() detalle = new EventEmitter<number>();

  verDetalle(): void {
    if (this.product) {
      this.detalle.emit(this.product.id);
    }
  }
}

Preguntas frecuentes

Por que --standalone false?

Angular 20 por defecto crea componentes standalone. Con --standalone false usamos modulos tradicionales (NgModule), que es el patron que seguiremos en todo el modulo.

Cuando uso [ ] y cuando {{ }}?

{{ }} para texto dentro de etiquetas. [ ] para atributos HTML: [src], [class], [disabled]. No puedes usar {{ }} en un atributo src.

Que es <router-outlet>?

Es el "hueco" donde Angular inserta el componente de la ruta activa. Esta en app.html. Sin el, las rutas no renderizan nada.
