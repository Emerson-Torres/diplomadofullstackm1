Historia y Contexto

Para entender jQuery hay que entender el caos que vino a resolver.

El problema que existía antes de jQuery

En los años 2000, JavaScript era una pesadilla. Cada navegador implementaba las APIs de forma diferente. El mismo código que funcionaba en Firefox fallaba en Internet Explorer:

el-infierno-2005.js — antes de jQuery
// Obtener un elemento — había que detectar el navegador manualmente
function getElement(id) {
  if (document.getElementById)  return document.getElementById(id);   // IE5+, Firefox
  if (document.all)             return document.all[id];                  // IE4
  if (document.layers)          return document.layers[id];               // Netscape 4
}

// Hacer AJAX — también cambiaba según el navegador
var xhr;
if (window.XMLHttpRequest) {
  xhr = new XMLHttpRequest();                    // IE7+, Firefox, Chrome
} else {
  xhr = new ActiveXObject("Microsoft.XMLHTTP");    // IE6 y anterior
}
xhr.open("GET", "/api/productos", true);
xhr.onreadystatechange = function() {
  if (xhr.readyState === 4 && xhr.status === 200) {
    var data = eval("(" + xhr.responseText + ")"); // inseguro pero era lo único
    console.log(data);
  }
};
xhr.send();
¿Ves el problema? 20 líneas para un simple GET, detección manual del navegador, y eval() para parsear JSON porque JSON.parse() no existía en todos los browsers. jQuery vino a limpiar todo esto.

La línea del tiempo

2006
Nace jQuery — creado por John Resig. Lema: "Write less, do more". Resuelve la incompatibilidad entre navegadores con una API única.
2008
Explosión de popularidad. Se convierte en la librería más usada del mundo. Casi todos los sitios lo incluían por defecto.
2010
jQuery UI y jQuery Mobile. Extienden con componentes de interfaz y soporte móvil. El ecosistema crece enormemente.
2013
Nacen React y Angular.js. Los frameworks modernos empiezan a cambiar el paradigma. jQuery sigue dominando, pero la era de los componentes comienza.
2015
ES6 (ECMAScript 2015) y fetch() llegan al estándar. JavaScript moderno incluye Promesas, fetch, y selectores nativos. Los navegadores ya son compatibles entre sí.
2019
Bootstrap 5 elimina jQuery. El framework CSS más popular lo abandona como dependencia. Señal clara: la era de jQuery como obligatorio terminó.
Hoy
~75% de los sitios web todavía lo usan (W3Techs 2025). WordPress, sistemas bancarios, ERPs y proyectos con 10+ años de historia siguen dependiendo de él. Por eso lo estudiamos.

¿Dónde lo vas a encontrar en el trabajo?

Sí lo vas a ver en…
  • Sitios WordPress y todos sus plugins
  • Sistemas bancarios y gubernamentales
  • ERPs y CRMs legacy (SAP UI, Salesforce clásico)
  • Librerías: DataTables, Select2, Datepicker
  • Proyectos de empresas con 10+ años
No deberías usarlo en…
  • Proyectos nuevos con Angular, React o Vue
  • Apps que ya usan ES6+ con fetch nativo
  • Cuando solo necesitas 1–2 funcionalidades
  • Apps móviles o de alto rendimiento
  • Cualquier proyecto que empieces hoy

El Ecosistema de Librerías JavaScript

jQuery no está solo — es parte de un universo de librerías que extienden lo que JS puede hacer.

¿Qué es una librería JavaScript?

Una librería es código que alguien ya escribió para resolver un problema común. En lugar de escribirlo tú desde cero, la incluyes y usas sus funciones.

Sin librería — tú escribes todo
// Formatear una fecha manualmente
function formatDate(date) {
  const d = date.getDate().toString().padStart(2,'0');
  const m = (date.getMonth()+1).toString().padStart(2,'0');
  const y = date.getFullYear();
  return `${d}/${m}/${y}`;
}
// ... y así con cada caso especial

Librería vs Framework — la diferencia clave

Librería (jQuery, Axios, Chart.js)

Tú controlas el flujo. Llamas a la librería cuando quieres. Es una herramienta dentro de tu código.

"Yo decido cuándo y cómo usar Chart.js para pintar una gráfica."

Framework (Angular, React, Vue)

El framework controla el flujo. Te dice cómo estructurar tu app. Tú escribes código dentro de sus reglas.

"Angular me dice cómo organizar componentes, rutas y servicios."

Dos formas de agregarlo y los primeros pasos con la sintaxis $( ).

Formas de incluirlo

① CDN — la más rápida (la que usamos en clase)

index.html — incluir jQuery por CDN
<!DOCTYPE html>

  <div id="galeria"></div>

  <script src="https://code.jquery.com/jquery-3.6.0.min.js"></script>

  <!-- 2. Tu código que USA jQuery -->
  <script src="app.js"></script>
</body>
</html>

② npm — para proyectos con Node.js (lo verás en Angular)

terminal
npm install jquery

# Luego en tu archivo JS/TS:
import $ from "jquery";
Error común: $ is not defined — tu script se ejecuta antes de que jQuery cargue. Solución: jQuery siempre antes del </body>, y tu script después de jQuery.

$(document).ready() — esperar al DOM

document-ready.js
// Forma completa (jQuery clásico)
$(document).ready(function() {
  $("#btn").click(function() { console.log("Botón clickeado"); });
});

// Forma corta — exactamente igual (más usada)
$(function() {
  console.log("DOM listo");
});

// Equivalente en JS nativo moderno
document.addEventListener("DOMContentLoaded", function() { /* ... */ });
Hoy en día si pones tu script antes del </body>, el DOM ya está listo y no necesitas $(document).ready(). Pero lo verás en código legacy — es importante reconocerlo.

Sintaxis jQuery

jQuery traduce cada operación del DOM en una línea elegante. Todo pasa por $( ).

Selectores — igual que CSS

selectores.js
$("#titulo")          // por ID     → document.getElementById("titulo")
$(".tarjeta")         // por clase  → document.querySelectorAll(".tarjeta")
$("p")                // por tag    → todos los <p>
$("ul li")            // descendiente
$("input[type='text']") // por atributo
$("[data-id='5']")    // por data-*
$(":visible")         // solo los visibles
$(":first")           // primer elemento

Manipular contenido, clases y eventos

manipulacion-y-eventos.js
// ── CONTENIDO ────────────────────────────────────────────────
$("#titulo").text("Nuevo texto");        // ← como textContent
$("#caja").html("<b>HTML bold</b>");    // ← como innerHTML
$("#input").val();                      // leer valor de input
$("#galeria").empty();                   // vaciar contenido
$("#galeria").append("<p>nuevo</p>");   // agregar al final

// ── CLASES ───────────────────────────────────────────────────
$("#caja").addClass("activo");
$("#caja").removeClass("oculto");
$("#caja").toggleClass("resaltado");
$("#caja").hasClass("activo");          // → true/false

// ── MOSTRAR / OCULTAR ────────────────────────────────────────
$("#caja").hide();                      // display:none

// ── EVENTOS ──────────────────────────────────────────────────

// ── DELEGACIÓN — un listener para muchos elementos ───────────

$.ajax y $.get — AJAX con jQuery

La forma jQuery de hacer peticiones HTTP. Más verbosa que fetch, pero muy legible y omnipresente.

$.ajax — la función base

ajax-basico.js
$.ajax({
  url:     "https://fakestoreapi.com/products",
  method:  "GET",
  success: function(data) {
    // data ya viene parseado — jQuery llama a JSON.parse() internamente
    console.log(data[0].title);   // "Fjallraven Backpack"
  },
  error: function(xhr, status, err) {
    console.error("Error:", status, err);
  }
});

// Con todas las opciones útiles
$.ajax({
  url:        "https://fakestoreapi.com/products/1",
  method:     "GET",
  dataType:   "json",          // fuerza parseo JSON
  timeout:    5000,            // 5 segundos máximo
  beforeSend: function() {
    $("#spinner").show();       // mostrar loading
    $("#btn").prop("disabled", true);
  },
  success: function(data) {
    $("#resultado").html(`<h3>${data.title}</h3>`);
  },
  error: function() {
    $("#resultado").html("<p class='text-danger'>Error</p>");
  },
  complete: function() {        // ← como "finally" — siempre se ejecuta
    $("#spinner").hide();
    $("#btn").prop("disabled", false);
  }
});
complete en jQuery es el equivalente al finally de try/catch que viste en Clase 2. Siempre se ejecuta, haya éxito o error.

$.get, $.post y $.getJSON — atajos

ajax-atajos.js
// $.get() — atajo GET con callback
$.get("https://fakestoreapi.com/products?limit=4", function(data) {
  console.log(data);
});

// $.get() encadenado con .done() y .fail()
$.get("https://fakestoreapi.com/products?limit=4")
  .done(function(data) { console.log("✓ Éxito:", data.length); })
  .fail(function(err)  { console.error("✗ Error", err); });

// $.getJSON() — GET que garantiza JSON
$.getJSON("https://fakestoreapi.com/products/1", function(producto) {
  console.log(producto.title, "- $", producto.price);
});

// $.post() — atajo POST
$.post("https://fakestoreapi.com/products", {
  title: "Nuevo Producto", price: 29.99
}, function(response) {
  console.log("Creado con id:", response.id);
});

Patrón completo: galería con $.ajax

function cargarProductosJQ() {
  var $galeria = $("#galeria");
  var $btn     = $("#btn-cargar");

  $.ajax({
    url:        "https://fakestoreapi.com/products?limit=6",
    method:     "GET",

      $galeria.html("<div class='text-center py-4'><div class='spinner-border'></div></div>");

    },

    },
    error: function(xhr, status) {
      $galeria.html(`<div class="alert alert-danger">Error: ${status}</div>`);
    },
    complete: function() {
      $btn.prop("disabled", false).text("Cargar productos");
    }
  });
}

Con fetch() + async/await ✓
async function cargar() {
  const g   = document.getElementById("galeria");
  const btn = document.getElementById("btn");

  g.innerHTML  = "Cargando...";
  btn.disabled = true;

  try {
    const res  = await fetch("...fakestoreapi.com/products");
    const data = await res.json();
    g.innerHTML = data.map(crearTarjeta).join("");
  } catch(e) {
    g.innerHTML = "Error";
  } finally {
    btn.disabled = false;
  }
}

¿Cuándo usar jQuery y cuándo no?

Criterio profesional para tomar la decisión correcta según el contexto.

La regla general

✅ USA jQuery cuando…
  • El proyecto ya tiene jQuery y tu tarea es mantenerlo
  • Vas a integrar DataTables, Select2 o jQuery Validate
  • Es un proyecto WordPress o de plantillas HTML
  • Te lo pide explícitamente el equipo o cliente
✅ USA fetch/Axios cuando…
  • Estás en un proyecto nuevo
  • Usas React, Vue o Angular
  • Quieres tipado con TypeScript
  • Te importa el rendimiento y el peso del bundle

Escenarios reales

📋 Empresa con sistema legacy
Aprende a leer y mantener jQuery. No lo reescribas a menos que te lo pidan. El refactor cuesta tiempo y puede romper cosas.
🚀 Startup con proyecto nuevo
Usa Angular + HttpClient + TypeScript desde el inicio. No incluyas jQuery — no lo necesitas y añade peso innecesario.
🔧 Necesitas DataTables en Angular
Incluye jQuery solo para DataTables. Intégralo con declare var $: any. Es aceptable para casos puntuales.
📱 Proyecto WordPress
WordPress incluye jQuery por defecto. Úsalo — es el estándar del ecosistema y los hooks están construidos sobre él.

DataTables & Select2 en la práctica

Las dos librerías que más explican por qué jQuery sigue instalado en el 75% de la web. Ejemplo completo paso a paso.

El punto clave: DataTables y Select2 son librerías que dependen de jQuery. No funcionan sin él. Por eso cuando un proyecto necesita tablas con filtros/paginación o selects enriquecidos, jQuery entra aunque nadie lo haya pedido explícitamente.

Paso 1 — CDNs: qué incluir y en qué orden

El orden importa. Los CSS y los scripts pueden ir todos en el <head> siempre que jQuery vaya primero — DataTables y Select2 lo necesitan disponible cuando se cargan.

index.html — <head> completo
<head>
  <!-- CSS -->
  <link href="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/css/bootstrap.min.css" rel="stylesheet">
  <link href="https://cdn.datatables.net/1.13.8/css/dataTables.bootstrap5.min.css" rel="stylesheet">
  <link href="https://cdn.jsdelivr.net/npm/select2@4.1.0-rc.0/dist/css/select2.min.css" rel="stylesheet">
  <link href="https://cdn.jsdelivr.net/npm/select2-bootstrap-5-theme@1.3.0/dist/select2-bootstrap-5-theme.min.css" rel="stylesheet">

  <!-- Scripts — jQuery SIEMPRE PRIMERO -->
  <script src="https://code.jquery.com/jquery-3.6.0.min.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/bootstrap@5.3.3/dist/js/bootstrap.bundle.min.js"></script>
  <script src="https://cdn.datatables.net/1.13.8/js/jquery.dataTables.min.js"></script>
  <script src="https://cdn.datatables.net/1.13.8/js/dataTables.bootstrap5.min.js"></script>
  <script src="https://cdn.jsdelivr.net/npm/select2@4.1.0-rc.0/dist/js/select2.min.js"></script>
</head>
Error frecuente: si DataTables o Select2 cargan antes que jQuery obtienes jQuery is not defined. El orden no es negociable — jQuery siempre primero.

El HTML declara el <select> y la <table> vacíos. jQuery y las librerías los llenan dinámicamente. Las opciones y las filas las carga el script, no el HTML.

Paso 3 — Select2: activar y llenar desde la API

Primero se activa Select2 sobre el select vacío, luego $.ajax trae las categorías y llena las opciones dinámicamente:

app.js — Select2 + $.ajax de categorías
// 1. Activar Select2 sobre el select vacío
$("#slvCategories").select2({
  theme:       "bootstrap-5",
  placeholder: "Elige una categoría...",
  allowClear:  true
});

// 2. Cargar las categorías desde la API y llenar el select
$.ajax({
  type:    "GET",
  url:     "https://fakestoreapi.com/products/categories",
  success: function(response) {
    let $select = $("#slvCategories");

    $select.empty(); // quitar "Select one" inicial

    // Agregar "All" primero como opción para ver todos
    $select.append($("<option>").val("All").text("Select all"));

    // Agregar cada categoría que devuelve la API:
    // response = ["electronics", "jewelery", "men's clothing", "women's clothing"]
    response.forEach(element => {
      $select.append($("<option>").val(element).text(element));
    });
  }
});
$select.empty() limpia las opciones previas antes de agregar las nuevas. Sin esto, al recargar las opciones se acumularían.

Paso 4 — listarProductos(category): el corazón del ejemplo

Esta función decide la URL según la categoría, destruye la tabla anterior si existe y crea una nueva DataTable que hace su propio $.ajax internamente:

app.js — función listarProductos(category)
function listarProductos(category) {

  // 1. Decidir la URL según la categoría elegida
  let url;
  if (category === "All") {
    url = "https://fakestoreapi.com/products";
  } else {
    url = "https://fakestoreapi.com/products/category/" + category;
  }

  // 2. Destruir la tabla si ya existe una instancia activa
  //    Sin esto DataTables lanza: "Cannot reinitialise DataTable"
  if ($.fn.DataTable.isDataTable("#tblProducts")) {
    $("#tblProducts").DataTable().destroy();
  }

  // 3. Crear la DataTable — ella misma hace el GET con ajax:{}
  $("#tblProducts").DataTable({
    ajax: {
      url:     url,
      dataSrc: ""  // la API devuelve [] directo, no { data:[] }
    },
    columns: [
      { data: "id"          },
      { data: "title"       },
      { data: "price"       },
      { data: "description" },
      { data: "image"       }
    ],
    columnDefs: [{
      targets:   4,             // columna "image" (índice 4)
      orderable: false,         // no ordenable
      render: function(data) {
        return `<img width="50px" src="${data}"/>`;
        // render convierte la URL en una imagen visible
      }
    }]
  });
}
ajax: { url, dataSrc:"" }

DataTables hace el fetch internamente. dataSrc:"" indica que la respuesta es un array directo [], no un objeto con propiedad data.

columns: [{data:"campo"}]

Mapea cada propiedad del JSON a una columna. DataTables lee directamente el objeto — no hay que construir filas manualmente.

columnDefs: [{render}]

Personaliza cómo se pinta una columna. Aquí convierte la URL de imagen en un <img>. Se usa también para botones, fechas y badges.

Paso 5 — Conectar Select2 con listarProductos()

El evento change detecta cuándo el usuario elige una categoría y llama a listarProductos() con el nuevo valor. La tabla se destruye y se recrea con los datos del nuevo endpoint:

app.js — script completo y ordenado
// 1. Activar Select2
$("#slvCategories").select2({
  theme: "bootstrap-5", placeholder: "Elige una categoría...", allowClear: true
});

// 2. Cargar categorías
$.ajax({
  type: "GET", url: "https://fakestoreapi.com/products/categories",
  success: function(response) {
    let $select = $("#slvCategories");
    $select.empty();
    $select.append($("<option>").val("All").text("Select all"));
    response.forEach(element => $select.append($("<option>").val(element).text(element)));
  }
});

// 3. Cargar todos los productos al inicio
listarProductos("All");

// 4. Re-cargar al cambiar la categoría
$("#slvCategories").on("change", function() {
  let category = $(this).val(); // valor de la opción elegida
  listarProductos(category);
});

// 5. La función principal
function listarProductos(category) {
  let url = category === "All"
    ? "https://fakestoreapi.com/products"
    : "https://fakestoreapi.com/products/category/" + category;

  if ($.fn.DataTable.isDataTable("#tblProducts")) {
    $("#tblProducts").DataTable().destroy();
  }

  $("#tblProducts").DataTable({
    ajax: { url: url, dataSrc: "" },
    columns: [
      { data: "id" }, { data: "title" }, { data: "price" },
      { data: "description" }, { data: "image" }
    ],
    columnDefs: [{
      targets: 4, orderable: false,
      render: function(data) { return `<img width="50px" src="${data}"/>`; }
    }]
  });
}
¿Por qué destroy() antes de reinicializar? DataTables no permite crear dos instancias sobre el mismo elemento. $.fn.DataTable.isDataTable("#id") verifica si ya existe una antes de destruirla — evita el error "Cannot reinitialise DataTable" cuando la tabla todavía no se ha creado la primera vez.

DataTable con ajax

ajax:{url, dataSrc:""} hace el GET solo. columns:[{data}] mapea el JSON automáticamente.

destroy + reinit

isDataTable() + .destroy() antes de recrear la tabla al cambiar categoría.

Por qué esto justifica jQuery en proyectos reales: con menos de 30 líneas tienes búsqueda, paginación, ordenamiento por columna, filtrado por categoría desde la API y un select enriquecido. // ❌ JavaScript puro (Clases 1-3): JS no sabe qué forma tiene "data"
$.ajax({ url: "...products/1", success: function(data) {
  console.log(data.titlee);   // typo → undefined en producción — JS no avisa

// ✅ TypeScript (Clase 4): define la forma del objeto, el editor te avisa
interface Product {
  id:       number;
  title:    string;
  price:    number;
  image:    string;
  category:string;
}

async function cargar(): Promise<void> {
  const res  = await fetch("...products/1");
  const data: Product = await res.json();
  console.log(data.titlee);  // ← ERROR en el editor ANTES de ejecutar
  console.log(data.title);   // ← OK + autocomplete disponible ✓
}
