¿Qué es el Desarrollo FullStack?

Entendiendo el panorama completo antes de empezar a codear.

Las tres capas de una aplicación web

Cuando abres una aplicación como Amazon o Spotify, hay tres piezas trabajando juntas que no ves:

Frontend

Lo que el usuario ve e interactúa. Vive en el navegador.

  • HTML → estructura
  • CSS → estilos
  • JavaScript → comportamiento
  • Angular → framework que organiza todo esto
Backend

La lógica de negocio. Vive en un servidor.

  • Procesa peticiones HTTP
  • Aplica reglas de negocio
  • Se comunica con la base de datos
  • Spring Boot → lo que usaremos
Base de Datos

Donde persiste la información. Puede ser relacional o no relacional.

  • MySQL, PostgreSQL (relacionales)
  • MongoDB (no relacional)
  • MySQL → lo que usaremos
Desarrollador FullStack es quien puede trabajar en las tres capas. No necesariamente es experto en todo, pero entiende cómo se comunican y puede construir funcionalidades de punta a punta.

¿Qué son los Microservicios?

Imagina que Amazon es un solo programa gigante vs. que está dividido en servicios independientes: uno para pagos, otro para catálogo, otro para envíos…

🏚️ Monolito

Todo el código en una sola aplicación. Fácil al inicio, difícil de escalar. Si falla una parte, puede fallar todo.

🏙️ Microservicios

Servicios pequeños e independientes, cada uno con su propio backend y base de datos. Más complejo pero escalable. Lo veremos en el Módulo 4.

Por ahora: vamos a construir una aplicación bien estructurada. En el Módulo 4 aprenderemos a convertirla en microservicios.

¿Cómo se comunican Frontend y Backend?

A través de peticiones HTTP. El frontend hace una pregunta (request) y el backend responde (response).

1
Usuario hace clic en "Ver productos"
2
Frontend envía GET /api/products
3
Backend busca en la BD
4
Backend responde con JSON
5
Frontend muestra los datos

Los verbos HTTP más usados en REST:

VerboAcciónEjemplo

POSTCrear un recursoAgregar producto
PUTActualizar (completo)Editar producto
PATCHActualizar (parcial)Cambiar solo el precio
DELETEEliminarBorrar producto

JSON vs XML

Los dos formatos más comunes para intercambiar datos en la web. Hoy casi todo usa JSON.

¿Qué es JSON?

JSON (JavaScript Object Notation) es un formato de texto ligero para representar datos estructurados. Es fácil de leer para humanos y fácil de procesar para máquinas.

JSON viene de JavaScript pero es independiente del lenguaje. Cualquier lenguaje (Java, Python, PHP…) puede leer y escribir JSON.

Así se ve un producto de nuestra API en JSON:

producto.json 
{
  "id": 1,
  "title": "Fjallraven - Foldsack No. 1 Backpack",
  "price": 109.95,
  "description": "Your perfect pack for everyday use...",
  "category": "men's clothing",
  "image": "https://fakestoreapi.com/img/81fAn...",
  "rating": {
    "rate": 3.9,
    "count": 120
  }
}

Cuando la API devuelve múltiples productos, usa un array:

productos-array.json
[
  { "id": 1, "title": "Backpack", "price": 109.95 },
  { "id": 2, "title": "Casual T-shirt", "price": 22.3 },
  { "id": 3, "title": "Cotton Jacket", "price": 55.99 }
]

¿Qué es XML?

XML (eXtensible Markup Language) fue el estándar antes de JSON. Todavía se usa en sistemas legacy, SOAP y algunas configuraciones.

El mismo producto en XML:

producto.xml
<product>
  <id>1</id>
  <title>Fjallraven - Foldsack No. 1 Backpack</title>
  <price>109.95</price>
  <category>men's clothing</category>
  <rating>
    <rate>3.9</rate>
    <count>120</count>
  </rating>
</product>

Comparativa directa

CaracterísticaJSONXML
Legibilidad Fácil de leer Más verboso
Peso Ligero Más pesado
Soporte en JS Nativo (JSON.parse) Requiere parseo manual
Uso actual Estándar REST APIs Legacy / SOAP
Arrays Soporte nativo [ ] Repetir etiquetas
Conclusión: En el 95% de proyectos modernos usarás JSON. XML lo vas a encontrar principalmente en sistemas viejos o integraciones con SAP, bancos y servicios gubernamentales.
Demo: Parsear JSON en JavaScript
script.js
// Un string JSON (como lo que llega de una API)
const jsonString = '{"id":1,"title":"Backpack","price":109.95}';

// Convertir string → objeto JavaScript
const producto = JSON.parse(jsonString);
console.log(producto.title);   // "Backpack"
console.log(producto.price);   // 109.95

// Convertir objeto → string JSON (para enviar a una API)
const nuevoProducto = { title: "Zapatos", price: 79.99 };
const enviando = JSON.stringify(nuevoProducto);
console.log(enviando); // '{"title":"Zapatos","price":79.99}'

APIs REST

El puente de comunicación entre frontend y backend.

¿Qué es una API?

API significa Application Programming Interface. Es un contrato: "si me mandas esto, yo te devuelvo aquello".

Piénsalo como un restaurante:

  • El menú es la documentación de la API
  • Tu pedido es la petición (request)
  • El mesero es el protocolo HTTP
  • La cocina es el backend
  • El plato que te traen es la respuesta (response)

FakeStore API — Nuestra API de práctica

Durante el Módulo 1 usaremos https://fakestoreapi.com. Simula una tienda online con productos, carritos y usuarios.

fetch() — Tu herramienta para consumir APIs

La función nativa de JavaScript para hacer peticiones HTTP.

¿Qué es fetch()?

fetch() es una función de JavaScript que permite hacer peticiones HTTP de forma asíncrona. Devuelve una Promesa.

Asíncrono significa que el navegador no se detiene a esperar la respuesta. Sigue ejecutando el resto del código y cuando llega la respuesta, la procesa. Esto es clave para que la UI no se congele.

Anatomía de un fetch()

Hay dos formas de escribirlo. Ambas hacen lo mismo:

Forma 1: Con .then() — Promesas encadenadas

forma-promesas.js
fetch("https://fakestoreapi.com/products/1")
  .then(function(response) {
    // 1. La petición llegó. Convertimos a JSON
    return response.json();
  })
  .then(function(data) {
    // 2. Ya tenemos el objeto JavaScript
    console.log(data.title);
    console.log(data.price);
  })
  .catch(function(error) {
    // 3. Si algo falla, capturamos el error
    console.error("Error:", error);
  });

Forma 2: Con async/await — Más legible (la que usaremos)

forma-async.js
// La función debe ser "async" para usar "await" adentro
async function obtenerProducto() {
  try {
    const response = await fetch("https://fakestoreapi.com/products/1");
    const data = await response.json();

    console.log(data.title);  // "Fjallraven Backpack"
    console.log(data.price);  // 109.95
  } catch (error) {
    console.error("Error:", error);
  }
}

obtenerProducto(); // Llamamos la función
¿Cuál usar? async/await es más moderno, más legible y más fácil de mantener. Es lo que usaremos de aquí en adelante y lo que usa Angular internamente.

Código completo — Mini Tienda

Crea un archivo index.html y pega este código:

index.html
<!DOCTYPE html>
<html lang="es">
<head>
  <meta charset="UTF-8">
  <title>Mi Tienda</title>
  <style>
    body { font-family: sans-serif; padding: 20px; }
    .productos { display: flex; flex-wrap: wrap; gap: 16px; }
    .tarjeta {
      border: 1px solid #ddd; border-radius: 8px;
      padding: 16px; width: 200px;
    }
    .tarjeta img { width: 100%; height: 150px; object-fit: contain; }
    .tarjeta h3 { font-size: 14px; margin: 8px 0; }
    .tarjeta .precio { color: #2563eb; font-weight: bold; }
  </style>
</head>
<body>
  <h1>🛍️ Mi Tienda</h1>
  <div id="contenedor" class="productos"></div>

  <script>
    async function cargarProductos() {
      const res  = await fetch("https://fakestoreapi.com/products?limit=6");
      const data = await res.json();

      const contenedor = document.getElementById("contenedor");

      data.forEach(function(producto) {
        contenedor.innerHTML += `
          <div class="tarjeta">
            <img src="${producto.image}" alt="${producto.title}">
            <h3>${producto.title}</h3>
            <p class="precio">$${producto.price}</p>
          </div>
        `;
      });
    }

    cargarProductos(); // Se ejecuta al cargar la página
  </script>
</body>
</html>

Puntos clave de este ejercicio

  • document.getElementById("contenedor") — selecciona el div por su id
  • innerHTML += — agrega HTML al final del contenedor
  • Template literals `...${variable}...` — mezclan texto y variables de forma limpia
  • forEach — recorre cada elemento del array de productos
  • La función se llama al final para que se ejecute cuando carga la página
