AuthService y JWT

El servicio que maneja el ciclo completo de autenticacion: login, guardar el token, verificar sesion y logout.

Como funciona el flujo JWT

1
Usuario ingresa usuario y contrasena
2
POST a /auth/login con las credenciales
3
La API devuelve un token JWT
4
Se guarda en localStorage
5
El interceptor lo agrega a cada peticion
6
El guard lo verifica antes de rutas protegidas
Credenciales reales de FakeStoreAPI: username mor_2314 / password 83r5^_. El endpoint POST /auth/login devuelve un JWT real que puedes usar en las peticiones.

Paso 2 auth.service.ts

src/app/services/auth.service.tsTypeScript
import { Injectable } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class AuthService {

  private loginUrl = 'https://fakestoreapi.com/auth/login';

  constructor(private http: HttpClient) { }

  login(username: string, password: string): Observable<any> {
    return this.http.post<any>(this.loginUrl, { username, password });
  }

  saveToken(token: string): void {
    localStorage.setItem('token', token);
  }

  getToken(): string | null {
    return localStorage.getItem('token');
  }

  isLoggedIn(): boolean {
    return !!this.getToken();  // true si hay token, false si no
  }

  logout(): void {
    localStorage.removeItem('token');
  }
}

src/app/login/login.tsTypeScript
import { Component } from '@angular/core';
import { Router } from '@angular/router';
import { AuthService } from '../services/auth.service';

@Component({
  selector:    'app-login',
  templateUrl: './login.html',
  styleUrls:   ['./login.css']
})
export class LoginComponent {

  // Propiedades
  username: string = '';
  password: string = '';
  error:    string = '';
  loading:  boolean = false;

  constructor(
    private authService: AuthService,
    private router:      Router
  ) { }

  login(): void {
    this.loading = true;
    this.error   = '';

    this.authService.login(this.username, this.password).subscribe(
      (response) => {
        this.authService.saveToken(response.token);  // guardar el JWT
        this.router.navigate(['/users']);              // redirigir a la ruta protegida
      },
      (error) => {
        this.error   = 'Usuario o contrasena incorrectos.';
        this.loading = false;
      }
    );
  }
}

Interceptor HTTP

Se configura una sola vez y agrega el token JWT a todas las peticiones salientes de forma automatica.

Como funciona un interceptor

Un interceptor es una clase que "intercepta" cada peticion HTTP antes de que salga y puede modificarla. En este caso, agrega el header Authorization: Bearer <token>:

flujo con interceptor
// Sin interceptor — hay que agregar el token en cada llamada:
this.http.get('url', { headers: { Authorization: `Bearer ${token}` } });

// Con interceptor — se agrega automaticamente en TODAS las peticiones:
this.http.get('url');  // el interceptor agrega el token antes de enviar

Paso 5 Generar el interceptor con Angular CLI

En Angular 20 sí puedes generarlo con el CLI usando ng generate interceptor interceptors/auth. Después completas la lógica del archivo generado:

src/app/interceptors/auth.interceptor.ts — generado con CLITypeScript
import { Injectable } from '@angular/core';
import { HttpInterceptor, HttpRequest, HttpHandler } from '@angular/common/http';

@Injectable()
export class AuthInterceptor implements HttpInterceptor {

  intercept(req: HttpRequest<any>, next: HttpHandler) {
    const token = localStorage.getItem('token');

    if (token) {
      // Clonar la peticion y agregarle el header de autenticacion
      const cloned = req.clone({
        setHeaders: { Authorization: `Bearer ${token}` }
      });
      return next.handle(cloned);  // enviar la peticion modificada
    }

    return next.handle(req);  // si no hay token, enviar sin modificar
  }
}

Registrar el interceptor en app-module.ts:

src/app/app-module.ts — registrar el interceptorTypeScript
import { HTTP_INTERCEPTORS } from '@angular/common/http';
import { AuthInterceptor } from './interceptors/auth.interceptor';

@NgModule({
  // ... declarations, imports ...
  providers: [
    {
      provide:  HTTP_INTERCEPTORS,
      useClass: AuthInterceptor,
      multi:    true   // permite multiples interceptores en la misma app
    }
  ]
})
Por que multi: true? Angular permite tener varios interceptores activos al mismo tiempo. El multi: true le indica que este interceptor se agrega a la lista existente, en lugar de reemplazarla.

AuthGuard — Proteger rutas

Un guard verifica una condicion antes de que Angular active una ruta. Si la condicion falla, redirige al usuario.

Paso 6 Generar el guard con Angular CLI

En Angular 20 puedes crearlo con ng generate guard guards/auth y luego completar la validación:

src/app/guards/auth.guard.ts — generado con CLITypeScript
import { Injectable } from '@angular/core';
import { CanActivate, Router } from '@angular/router';
import { AuthService } from '../services/auth.service';

@Injectable({ providedIn: 'root' })
export class AuthGuard implements CanActivate {

  constructor(
    private authService: AuthService,
    private router:      Router
  ) { }

  canActivate(): boolean {
    if (this.authService.isLoggedIn()) {
      return true;  // hay token — puede entrar
    }

    // No hay token — redirigir al login
    this.router.navigate(['/login']);
    return false;
  }
}
Como funciona en la ruta: cuando el usuario intenta navegar a /users, Angular llama a AuthGuard.canActivate() antes de cargar el componente. Si devuelve true, carga la pagina. Si devuelve false, redirige a /login.

CartService y BehaviorSubject

Estado compartido del carrito entre todos los componentes. Cualquier cambio se propaga automaticamente al navbar y a la pagina del carrito.

Que es BehaviorSubject

Un BehaviorSubject es un Observable especial que guarda el ultimo valor emitido y lo entrega inmediatamente a cualquier componente que se suscriba. Es la forma recomendada de compartir estado en Angular:

Codigo que se vuelve dificil de mantener
// Cada componente tiene su propia copia
// y hay que sincronizarlas manualmente
// ProductsComponent:
carrito = [];

// AppComponent (navbar):
contadorCarrito = 0;
// Hay que actualizar ambos en cada cambio
Como mejorar: BehaviorSubject compartido
// Una sola fuente de verdad en CartService
cartItems$ = new BehaviorSubject([]);

// Cualquier componente se suscribe:
cartService.cartItems$.subscribe(items => {
  this.contadorCarrito = items.length;
});
// Se actualiza automaticamente

src/app/services/cart.service.tsTypeScript
import { Injectable } from '@angular/core';
import { BehaviorSubject } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class CartService {

  // BehaviorSubject — la fuente de verdad del carrito
  private cartItems = new BehaviorSubject<any[]>([]);
  cartItems$ = this.cartItems.asObservable();  // expuesto como Observable (solo lectura)

  constructor() {
    // Cargar el carrito guardado al iniciar la app
    const saved = localStorage.getItem('cart');
    if (saved) {
      this.cartItems.next(JSON.parse(saved));
    }
  }

  private saveToLocalStorage(items: any[]): void {
    localStorage.setItem('cart', JSON.stringify(items));
  }

  addToCart(product: any): void {
    const current = this.cartItems.getValue();
    const updated = [...current, product];   // spread — no mutar el array original
    this.cartItems.next(updated);
    this.saveToLocalStorage(updated);
  }

  removeFromCart(index: number): void {
    const current = this.cartItems.getValue();
    current.splice(index, 1);
    this.cartItems.next([...current]);
    this.saveToLocalStorage([...current]);
  }

  clearCart(): void {
    this.cartItems.next([]);
    this.saveToLocalStorage([]);
  }

  getTotal(): number {
    return this.cartItems.getValue().reduce((sum, item) => sum + item.price, 0);
  }
}

Navbar dinamico

El componente raiz suscrito al carrito y al estado de autenticacion. El contador y el boton Login/Logout reaccionan en tiempo real.

Paso 9 app.ts actualizado

src/app/app.tsTypeScript
import { Component, OnInit } from '@angular/core';
import { Router } from '@angular/router';
import { AuthService } from './services/auth.service';
import { CartService } from './services/cart.service';

@Component({
  selector:    'app-root',
  templateUrl: './app.html',
  styleUrls:   ['./app.css']
})
export class AppComponent implements OnInit {

  contadorCarrito: number = 0;

  constructor(
    public  authService: AuthService,  // public para usarlo directamente en el HTML
    private cartService: CartService,
    private router:      Router
  ) { }

  ngOnInit(): void {
    // Suscribirse al carrito — el contador se actualiza automaticamente
    this.cartService.cartItems$.subscribe(items => {
      this.contadorCarrito = items.length;
    });
  }

  logout(): void {
    this.authService.logout();
    this.router.navigate(['/login']);
  }
}

Errores comunes y sus soluciones

1 El interceptor no agrega el token

Red / DevTools — las peticiones no tienen el header Authorization
Las peticiones a /users llegan sin token
Verificar que el interceptor esta registrado en providers de app-module.ts con { provide: HTTP_INTERCEPTORS, useClass: AuthInterceptor, multi: true }. Es el error mas frecuente al agregar interceptores.

2 El guard no redirige — entra a /users sin login

app-routing-module.ts
Se puede acceder a /users sin haber hecho login
Verificar que la ruta tiene canActivate: [AuthGuard]. Tambien importar AuthGuard en app-routing-module.ts: import { AuthGuard } from './guards/auth.guard'.

3 El contador del carrito no se actualiza en el navbar

app.ts
contadorCarrito siempre muestra 0
Verificar que en ngOnInit() esta la suscripcion: this.cartService.cartItems$.subscribe(items => this.contadorCarrito = items.length). Sin la suscripcion, el componente no recibe los cambios del BehaviorSubject.

Preguntas frecuentes

Por que public authService en AppComponent?

Para poder llamar a authService.isLoggedIn() directamente en el HTML. Las propiedades private no son accesibles desde el template. Solo las propiedades public (o sin modificador) pueden usarse en el HTML.

Cual es la diferencia entre Observable y BehaviorSubject?

Un Observable normal solo emite valores cuando hay nuevos datos. Un BehaviorSubject siempre tiene un valor actual y lo entrega inmediatamente a cualquier nuevo suscriptor. Por eso es ideal para el estado del carrito: cuando el navbar se carga, recibe el conteo actual sin esperar.

El token de FakeStoreAPI es seguro para produccion?

No — es una API de prueba para aprendizaje. En produccion el JWT lo genera tu propio backend (Spring Boot en Modulo 2) con una clave secreta real. El flujo es identico: POST login → token → localStorage → interceptor.
