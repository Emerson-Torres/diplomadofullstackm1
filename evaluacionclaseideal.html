Ejercicio Practico — Modulo 1

Catalogo de Productos con Comparador

Construiras una aplicacion de catalogo de productos usando DummyJSON. Sin login, sin guards, sin interceptores. El foco esta en componentes, servicios, routing y una logica de comparacion que persiste en localStorage.

3 dias Individual 100 puntos DummyJSON API
Este ejercicio consolida Clases 5 y 6. Aplicas exactamente los mismos conceptos del modulo: componentes con @Input/@Output, un servicio centralizado con HttpClient, routing con parametros de ruta, y localStorage para persistir datos entre navegaciones. No hay nada nuevo — solo debes demostrarlo en un proyecto propio.
Catalogo con filtros

Lista de productos consumida desde DummyJSON. Filtro por categoria usando el endpoint correcto. Busqueda por nombre en tiempo real.

Vista de detalle

Ruta /product/:id con ActivatedRoute. Muestra descripcion, precio con descuento aplicado, stock, marca y resenas.

Comparador

El usuario selecciona hasta 3 productos para comparar. La seleccion persiste en localStorage. La ruta /comparar muestra la tabla comparativa.

Contexto de la aplicacion

La aplicacion se llama ProductCompare. Es un catalogo de productos donde el usuario puede explorar el inventario de DummyJSON, ver el detalle de cada producto con su descuento calculado, y marcar hasta 3 productos para compararlos lado a lado.

La logica del comparador es lo que requiere razonar:

  • Solo se pueden agregar hasta 3 productos a la comparacion. Si ya hay 3, el boton se deshabilita en todos los demas.
  • Si un producto ya esta en la comparacion, el boton cambia a "Quitar de comparacion".
  • La lista de comparacion se guarda en localStorage["comparacion"] y sobrevive si el usuario recarga la pagina o navega entre rutas.
  • La ruta /comparar muestra una tabla con los productos seleccionados, donde se pueden ver sus diferencias de precio, rating, stock y descuento de un vistazo.
Por que es diferente a un CRUD: la logica del comparador no es un simple "agregar y quitar". El limite de 3, el estado del boton segun si ya esta en la lista, y la persistencia requieren pensar en como estructurar el servicio y como comunicar el estado al componente hijo via @Input.

La API: DummyJSON

Los mismos endpoints de productos que vienen en el modulo, sin autenticacion. Acceso libre, sin API key.

Endpoints que usaras

MetodoEndpointDescripcionDonde se usa
GET /products?limit=20 Lista paginada de productos. Devuelve un objeto con la clave products que contiene el array. products.ts — ngOnInit
GET /products/{id} Detalle completo de un producto: descripcion, precio, descuento, stock, marca, resenas. product-detail.ts
GET /products/search?q=phone Busqueda por nombre. Devuelve el mismo formato que /products. products.ts — busqueda
GET /products/category-list Array de strings con los nombres de todas las categorias disponibles. products.ts — poblar el select
GET /products/category/{nombre} Productos filtrados por categoria. Mismo formato que /products. products.ts — filtro
Diferencia importante con FakeStoreAPI: DummyJSON no devuelve el array directamente. La respuesta de /products es un objeto: { products: [...], total: 194, skip: 0, limit: 20 }. Tienes que acceder a response.products — no directamente a response.

Requerimientos

Lo que debe funcionar en la entrega, organizado por nivel.

Nivel 1 Proyecto, servicio y listado

30 pts

  • La vista de detalle lee el :id de la URL con ActivatedRoute.snapshot.paramMap.get('id') y lo usa para llamar a product.service.ts.
  • El detalle muestra: imagen grande (images[0] o thumbnail), nombre, categoria, marca, descripcion completa, rating y stock.
  • El precio se muestra de dos formas: el precio original (price) tachado con text-decoration: line-through, y el precio con descuento calculado con la formula price * (1 - discountPercentage / 100).
  • Las resenas del producto se listan con *ngFor: nombre del autor, comentario y rating de cada una.
  • El boton "Volver al catalogo" navega a /products con routerLink.
Nivel 3 Comparador con localStorage
40 pts
  • comparador.service.ts gestiona la lista de comparacion. Expone los metodos: agregar(product), quitar(productId), estaEnComparacion(productId), limiteAlcanzado() y getComparacion().
  • La lista de comparacion se guarda en localStorage["comparacion"] y se carga en el constructor del servicio. Al recargar la pagina, los productos seleccionados siguen ahi.
  • El maximo de productos en comparacion es 3. limiteAlcanzado() devuelve true cuando ya hay 3.
  • El componente ProductCard recibe dos inputs adicionales: @Input() enComparacion: boolean y @Input() limiteAlcanzado: boolean. El padre (Products) calcula estos valores usando el servicio y los pasa al hijo.
  • El boton en la tarjeta muestra "Comparar" si el producto no esta en la lista, "Quitar" si ya esta. El boton se deshabilita ([disabled]) cuando el limite es 3 y el producto no esta en la lista.
  • El navbar muestra el contador de productos en comparacion: "Comparar (2/3)". El numero se actualiza cada vez que se agrega o quita un producto sin recargar.
  • La ruta /comparar muestra una tabla con los productos seleccionados. Columnas: imagen, nombre, precio original, precio con descuento, rating y stock. Si no hay productos seleccionados muestra un mensaje y un enlace a /products.
  • Desde la pagina /comparar se puede quitar individualmente cada producto de la comparacion.
No se evalua la apariencia visual. Bootstrap por defecto es suficiente. Lo que se evalua es que la logica funcione: el servicio, los inputs al componente hijo, la persistencia y el limite de 3.

Logica del comparador

Las partes que requieren razonar. Se dan pistas del enfoque, no el codigo completo.

product.service.ts — cuidado con la respuesta

DummyJSON no devuelve el array directamente. La respuesta de /products tiene este formato:

pista — extraer el array de la respuestaTypeScript
getProducts(): Observable<any[]> {
  // La respuesta es { products: [...], total: 194, skip: 0, limit: 20 }
  // Hay que extraer el array con .pipe(map(...))
  return this.http.get<any>(`${this.apiUrl}?limit=20`).pipe(
    map((res) => res.products)
  );
}

getCategories(): Observable<string[]> {
  // Este endpoint SI devuelve directamente un array de strings
  return this.http.get<string[]>(`${this.apiUrl}/category-list`);
}
El import de map: import { map } from 'rxjs/operators'. Este operador transforma el valor que emite el Observable antes de que llegue al .subscribe().

comparador.service.ts — estructura del servicio

pista — comparador.service.ts — estructura baseTypeScript
import { Injectable } from '@angular/core';

@Injectable({ providedIn: 'root' })
export class ComparadorService {

  private MAX = 3;
  private items: any[] = [];

  constructor() {
    // Cargar los productos guardados al iniciar
    const saved = localStorage.getItem('comparacion');
    if (saved) this.items = JSON.parse(saved);
  }

  private persistir(): void {
    localStorage.setItem('comparacion', JSON.stringify(this.items));
  }

  getComparacion(): any[] {
    return this.items;
  }

  estaEnComparacion(productId: number): boolean {
    return this.items.some(p => p.id === productId);
  }

  limiteAlcanzado(): boolean {
    return this.items.length >= this.MAX;
  }

  agregar(product: any): void {
    if (this.limiteAlcanzado() || this.estaEnComparacion(product.id)) return;
    this.items.push(product);
    this.persistir();
  }

  quitar(productId: number): void {
    this.items = this.items.filter(p => p.id !== productId);
    this.persistir();
  }
}
Por que no se usa BehaviorSubject aqui: a diferencia del carrito de la Clase 7, el comparador no necesita reactividad automatica. El navbar actualiza el contador llamando directamente a comparadorService.getComparacion().length despues de cada accion. Es una solucion mas simple y suficiente para este ejercicio.

Y en product-card.ts, los tres inputs y el output:

pista — product-card.tsTypeScript
export class ProductCard {
  @Input() product:         any     = null;
  @Input() enComparacion:   boolean = false;
  @Input() limiteAlcanzado: boolean = false;
  @Output() toggleComparacion = new EventEmitter<void>();

  toggle(): void {
    this.toggleComparacion.emit();
  }
}

El template del hijo decide que mostrar en el boton:

pista — product-card.html — boton del comparadorHTML
<!-- El boton tiene 3 estados posibles -->
<button
  class="btn btn-sm"
  [class.btn-primary]="!enComparacion"
  [class.btn-warning]="enComparacion"
  [disabled]="limiteAlcanzado && !enComparacion"
  (click)="toggle()">
  {{enComparacion ? 'Quitar' : (limiteAlcanzado ? 'Lleno' : 'Comparar')}}
</button>
Los tres estados del boton: si el producto ya esta en la lista muestra "Quitar" en amarillo. Si no esta y el limite es 3 muestra "Lleno" deshabilitado. Si no esta y hay espacio muestra "Comparar" en azul. Este es el tipo de logica condicional en el template que el ejercicio evalua.

app.ts — navbar con contador

El componente raiz muestra cuantos productos hay en comparacion. A diferencia de la Clase 7 no hay suscripcion — simplemente llama al servicio en el template:

pista — app.ts y app.html — contador en el navbarTypeScript
// app.ts — el servicio como public para accederlo desde el template
export class App {
  constructor(public comparadorService: ComparadorService) { }
}

// app.html — el contador se calcula directo en el template
<a class="nav-link" routerLink="/comparar">
  Comparar ({{comparadorService.getComparacion().length}}/3)
</a>
Angular detecta los cambios automaticamente. Cada vez que el usuario hace clic en "Comparar" o "Quitar" en la tarjeta, Angular re-evalua las expresiones del template — incluyendo comparadorService.getComparacion().length — y actualiza el contador sin que tengas que hacer nada extra.
